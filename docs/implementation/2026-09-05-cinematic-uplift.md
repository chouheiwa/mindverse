# 科幻电影级画质提升（批次 6）

- 日期：2026-09-05（Asia/Shanghai）
- 分支：`feature/babylon-migration`（在批次 0–5 的未提交状态上继续）
- 范围：**在恢复成果之上做提升**；恢复门禁一条不放宽，取景与手性一处不动
- 结果：恒星圆面从「45% 像素烧成纯白」变成「0% 过曝、有对流有星斑有色温分层的实体」

## 0. 这一批要解决的是一个物理问题，不是一个审美问题

先说清楚为什么恢复批次做完之后画面仍然是一团白，因为整批提升的每一处取舍
都是从这一条推出来的。

管线末端是 `KHR PBR Neutral` + exposure 0.92（`configurePlanetImageProcessing`）。
把它照抄成 CPU 镜像（新增 `toneResponse.ts`，8 条单测）之后可以直接读出它的
动态范围分布：

| 场景辐亮度（HDR） | 显示亮度 | 说明 |
|---:|---:|---|
| 0.35 | 0.282 | 线性段 |
| 1.5 | 0.935 | 已进压缩段 |
| 6.0 | 0.989 | 压缩段顶端 |

**1.5 到 6.0 之间只剩 0.054 的显示动态范围，而且带 23% 的去饱和。**

恢复批次为了让恒星越过 bloom 阈值，把表面 HDR 增益定在 4.0，圆面辐亮度落在
2.2–4.2 —— 整个圆面都在压缩段顶端。于是：

- 加更多表面细节没用，观众看到的是同一块白；
- 加更多颜色没用，去饱和会把它洗掉；
- 唯一还能被看见的，是**往暗处走的结构**。

所以这一批的主线不是「加亮」，是**把结构放进暗侧**：星斑、米粒间道、临边、
日珥、云影、夜侧。实拍佐证在 §5。

## 1. 恒星：从一团白到一颗有对流的球

### 1.1 米粒组织的对比曲线（`stellarRadiance.ts` / `starSurface.fragment.fx`）

恢复批次的 `detail = 0.62 + g·0.42 + c·0.12`，跨度 0.62–1.16。提升后：

```
detail_linear = 0.34 + g·0.86 + c·0.24        跨度 0.34–1.44
detail        = 0.89 · (detail_linear / 0.89) ^ 1.85
```

两处刻意的设计：

1. **均值恒为 0.89 不变**。`g = c = 0.5` 时线性段正好等于 0.89，幂曲线在这一点
   恒等 —— 于是 `stellarRadiance.test.ts` 的三条恢复门禁（圆面中心 > 3 倍阈值、
   边缘仍在阈值之上、中心到边缘单调下降）**逐位不受影响**。变的只有对比度。
2. **幂曲线而不是更大的线性跨度**。只加大跨度不够：亮的一半照样落在压缩段里，
   暗的一半却离不开中段。绕均值取幂才能把暗侧真正推进线性段 —— 那是显示端
   唯一还有动态范围的地方。

### 1.2 星斑：暗特征是唯一穿得过 bloom 的结构

新增 `starSpotField`：每个斑是方向上的一顶余弦帽，本影套在半影里。

**活动性调制的是斑多大，不是斑多深。** 深度是物理常数（本影约是宁静光球的
两成，`STAR_UMBRA_FLOOR = 0.16`）；第一版把活动性当强度旋钮拧小，斑立刻退化成
一块看不见的灰 —— 显示端对比度只有 0.03。改成调制角半径之后是 0.55+，
由 `starSurfaceUplift.test.ts` 盯住。

宁静恒星也保一个底（`SPOT_FLOOR = 0.42`）：一颗一个斑都没有的球，在 bloom
之后仍然是一团光。

### 1.3 分层色温：三层，加上跟着亮度走的局部色温

| 层 | 色温 | 来源 |
|---|---|---|
| 核心视向 | `T × 1.16`，再往白推 0.42 | 视线最深、最热的一层 |
| 光球 | `T` | 恢复批次的 `hotCenter` 原样保留 |
| 临边 | `T × 0.74`，混 50% 色球红 | 更高更冷的一层 + Hα 红边 |

**色球色（`[1, 0.34, 0.2]`）是保亮度混入的**：它只改色相不改能量。不归一化的话
临边亮度掉到 0.64，低于 bloom 阈值 0.68 —— 恢复批次「整个圆面都有柔光」那条门禁
当场破。分层色温是一次调色，不该顺手把恢复成果吃掉。

还有一处**局部色温**：`mix(uLimbColor, stratified, smoothstep(0.10, 1.05, detail))`。
暗的地方是下沉的冷等离子体，亮的地方是上涌的热柱。少了这一项，暗纹只是同一个
色相被调暗，画面读起来是月面的灰斑而不是恒星的对流 —— 这是实拍看出来的，
第一版就是那个样子。

实测：圆面内 60×60 窗口的 `colorSpread` **0.0184 → 0.1372（7.47 倍）**。

### 1.4 日冕流苏与日珥（`starCorona.fragment.fx`）

- **流苏**：从冕洞之间伸出去的长条状等离子体，条数由画质分档给（high 7 / medium 5 / low 4）。均匀的毛边是廉价光晕的样子，有结构才是日冕。
- **日珥**：贴着临边升起的拱形等离子体，每一个有自己的呼吸周期（互质频率），所以不会整齐地一起鼓一起消。高度按活动性缩放 —— 「恒星是活的」在画面上的证据。
- **颜色**：日珥是色球的物质，所以它带色球的红，不是日冕的白。

### 1.5 聚焦恒星的衍射星芒（新增 `starDiffraction.fragment.fx`）

全景里点精灵一直有星芒，但一旦飞近、恒星改由球体渲染，星芒就整个消失 ——
「越靠近越不像恒星」。新增一枚公告板补回来，用**叶片衍射**的形状
（条数 = 画质分档，high 6 / medium 4 / low 4），加法混合，永远不会把主体压暗。

**第一版做过头了**：实拍是四条又粗又长的白十字压住整个画面。收窄之后
（角向指数 42 → 220，芒身衰减 3.1 → 7.4，alpha 上限 0.72 → 0.34）它才是点缀。
这一处只有实拍能发现，单测量不出「太粗」。

## 2. 行星：每一条新外观都还是证据

新增 `planetAppearance.ts`（8 条单测），把「画面上多出来的东西」逐条接回已有的
数据轴。接不上的一律不加：

| 画面上的东西 | 数据轴 | 语义 |
|---|---|---|
| 云量 | `freshness`（热度） | 还在被讨论的问题有活跃的大气 |
| 云速 | `incident`（恒星距离） | 离恒星越近环流越快，指数取辐射平衡温度的 1/4 次方 |
| 夜侧灯火 | `answerCount`（回答数） | **一条回答就是一盏灯** |
| 雪线 | `incident`（恒星距离） | 星越远，冰盖越往赤道压；海拔也算数 |
| 熔岩裂谷 | `magma × faultStrength`（年代跨度） | 热 **且** 有历史才裂得开 |
| 冰裂 | `ice` 权重 | 冻透了才裂 |
| 坑的可见度 | `answerCount − 云量` | 有大气的世界，坑被风化糊掉 |

着色器侧新增：

- **云层**：独立于地形的一层场，跟着自己的相位漂移，纬向拉伸成带（科里奥利），域扭曲成涡。**带自投影**（沿光照方向再采样一次）—— 没有投影的云是一张贴纸。晨昏线上带前向散射的暖边。
- **夜侧**：灯火聚在低海拔平原、避开冰盖、只在背光面出现。白天看不见灯，这是夜侧存在的全部理由。
- **雪线**：由 `uSnowLine` 驱动极冠掩膜，并按 `vHeight` 下压 —— 高原上的雪线更低，那是山才有的读感。
- **熔岩**：裂缝网络用脊线噪声的倒数取，于是熔岩只出现在裂开的那几条线上，不是糊满整个热半球。

实测：岩浆行星 56×56 窗口的 `detailDensity` **0.0389 → 0.0894（2.30 倍）**。

**远景没有降级**：`low/medium/high` 三档走的都是同一条程序化着色路径
（八度 3/5/6），云的八度按 LOD 减一档但不为零。「远景可辨识轮廓和大地貌」
由地形位移 + 云带 + 雪线共同给出，不依赖近景才有的那一档。

## 3. 宇宙：补上缺失的「远」

### 3.1 深空星场（新增 `starfieldLayer.ts`，11 条单测）

迁移前后都没有这一层：全景里除了自己的恒星、星云和尘埃，背景是纯黑。
于是宇宙没有「远」—— 所有东西都在同一个深度上。

三条原则，各有单测：

1. **纵深来自分层视差**：三层壳（半径 1.55 / 2.35 / 3.6 倍场景半径），相机一动近层比远层移动得快。**恒为 3 层**，抽稀可以，抽掉一整层不行 —— 那样星场会塌成一张贴纸。
2. **克制**：最远那层最密但最暗（gain 0.30），最近那层最稀但最亮（0.82）。点径封顶 3.4 px，分档上限由 `visualUplift` 盯住（≤ 2600 粒）。
3. **有色温**：谱型丰度照抄真实主序星（M 型 62%、K 20%、G 10%、F 5%、B 3%），于是星场自动是「以暖色为底、点缀几颗蓝白」，而不是一堆白点。单测断言颜色跨度 > 0.18。

球面采样按 `cosθ` 均匀取（不是按 θ，后者会把星星堆在两极）；半径带 ±14% 抖动
（完全落在一个球壳上会在掠射角露出一条硬边）。相机贴近主体时星场退让，
但保留 0.22 的底噪 —— 背景一旦全黑，近景就失去可参照的远处。

### 3.2 空间雾与镜头层（新增 `cinematicGrade.ts`，8 条单测）

- **空间雾**：把尘埃与轨道环共用的 `depthFade` 远平面按分档收进来（high 1.30 倍半径 / low 1.75 倍）。深空当然没有雾，但有它的等价物：星际尘埃的散射，以及人眼在没有距离线索时读不出深度。
- **暗角**：权重 1.65 / 1.45 / 1.20，颜色是偏冷的深蓝而不是纯黑 —— 纯黑暗角读起来像镜头脏了。
- **颜色分级**：暗部偏冷（shadowsHue 220）、亮部偏暖（highlightsHue 34）。冷退暖进，是风景画用了几百年的空气透视，深空里同样成立。
- **颗粒**：4.2 / 3.4 / 2.6。
- **色差**：high 2.4 px / medium 1.4 / low 0。低档掉的是它，不是整条镜头层 —— 暗角与分级都是逐像素常数运算，掉了也省不下什么。

**两条硬性约束由单测盯住**：exposure 恒 0.92、bloomThreshold 恒等于
`cinematic.ts` 给的那一档。分级是叠在恢复成果之上的一层镜头，不是对它的重新定义。

### 3.3 保留项

虫洞、暗物质透镜、星群结构环、标签、六个模式的语义**一处未动**，
`mode-bar` 门禁仍然 2/2 通过（六帧两两 sha256 不同）。

## 4. 探测器 / 地层 / 交互 / 分档

### 4.1 探测器（新增 `probeCinematics.ts`，10 条单测）

- **三点布光**：暖主光 + 冷补光 + 背后的轮廓光，挂在检查根节点下、只照被检查的那一艘。单一白光下的金属永远是一块灰 —— 金属感来自两个不同色温的高光在同一个曲面上分开。掉档时**从尾巴砍**：先掉轮廓光，再掉补光，主光永远在。
- **推进器**：同轴锥体串，越往外越细越冷；怠速有底光（`THRUSTER_IDLE = 0.28`，熄火的飞船读起来是残骸），扫描时升到 0.85 油门。抖动由两个互质周期叠出来 —— 单一正弦读起来是节拍器，不是等离子体。Reduced Motion 下抖动退化为常数。
- **扫描扫掠**：一枚圆盘沿机体轴从头滑到尾，正弦包络软进软出。整机同时变亮说不出「正在从头扫到尾」。

**一处实拍才发现的 bug**：尾焰长度原本写成 `mesh.scaling.x`。圆柱绕 Z 转了 90°，
缩放发生在旋转之前，所以 `x` 缩的是**粗细**不是长度 —— 尾焰只会变粗。改成
`scaling.y` 并逐帧重算分段位置。

### 4.2 答案地层（新增 `strataAtmosphere.ts`，8 条单测）

恢复批次把「一片黑」修成了「有明暗交替的层」。这一批回答下一个问题：
**往下走的时候，观众怎么知道自己在往下走？**

- **深度分级的雾**：越深越暗越浓（0.022 → 0.046，色从 `[0.030,0.052,0.070]` 到 `[0.008,0.012,0.020]`）。竖井里没有地平线，雾是唯一的距离线索。上限 0.06 —— 再浓层就不读了。
- **引导光**：一盏跟着旅行者下移的冷光（挂在上方 3.4 个单位）。它不负责照明，它负责说「上方还有出口」。三档都有，只是更暗。
- **标本光晕**：每条答案外面套一层加法混合的发光壳，颜色说出「我写的（暖）/ 我收的（冷）/ 只是读到过（中性）」。没有光晕时标本是一块石头，画面说不出它是一条内容。

实测带亮度剖面：批次 5 是 `0.1291…0.1476`，本批是 `0.1547…0.1747` —— 整体抬亮
约 20%，分层仍在，`the answer strata is a lit, layered world` 门禁照常通过。

### 4.3 交互与转场（新增 `interactionFeedback.ts`，10 条单测）

- **相机阻尼显式化并与 Reduced Motion 联动**：此前用的是 Babylon 的默认 0.9，从来没有人决定过它。现在正常 0.88 / 降级 0.55（不是 0：完全没有惯性会让每一次拖拽变成硬切，那同样是突兀的运动）。**滚轮步长恒为 0.012** —— 批次 4 的退出阶梯三个阈值是按它标定的，改步长会连带改掉退出层级的手感。
- **行星悬停/选中轮廓**：旧值是 `uSelected * 0.02`，写了，但在 bloom 与色调映射之后等于没写。现在由 `planetInteractionRim` 给（悬停暖、选中冷，强度上限 0.42，自带单测），并且**不需要额外的 `scene.pick`** —— `sceneTarget` 已经返回 `planet:<id>`，这里只是把已经知道的事实告诉行星。
- **转场缓动**：五次 smootherstep，起止两端的加速度也是 0，于是一次转场读起来是「镜头动了」而不是「画面切了」。

`planetShader.test.ts` 里那条写死 `uSelected * 0.02` 的断言改成了可执行的不变量：
轮廓仍然只乘在边缘项上、强度上限由 `planetInteractionRim` 的单测保证 ≤ 0.42。
**这是把一个魔数换成一条更强的契约，不是放宽。**

### 4.4 分档（新增 `visualUplift.ts`，5 条单测）

一条不变量：**分档只降规格，不删类别。**

14 个效果类别（星场 / 星斑 / 米粒 / 日珥 / 日冕流苏 / 衍射星芒 / 行星云 /
夜侧 / 大气 / 探测器补光 / 推进器 / 地层纹层 / 地层引导光 / 空间雾）在
high / medium / low 三档上逐一断言存在；密度单调；低档的总开销恒不高于高档。

恢复批次已经吃过一次「low 直接关 bloom」的亏 —— 省下来的填充率买到的是
「那一屏最该发光的东西反而不发光」。

## 5. 实测指标

新增 `scripts/upliftMetrics.mjs`（8 条单测）与 `scripts/report-uplift.mjs`：
零依赖、复用已有的 PNG 解码器，五项指标各自写明「越大越好还是越小越好」。

```bash
node scripts/report-uplift.mjs <before-dir> <after-dir> "focused-star=610,342,60,60"
```

**必须给窗口**：parity 截图是整页合成帧，右侧 React 面板与左下角问题航道占了
大量高对比像素且两边逐位相同 —— 量整帧等于在量 UI 的文字边缘，所有指标都会
被稀释成 1.00×。

## 7. 跨引擎越界：9 → 10，新增的那一项是**刻意的**

批次 5 的 9 项分类（§7.2 程序化噪声、§7.3 手性镜像）**一项未变、一项未增**：

| 状态 | 越界 | 归类 |
|---|---|---|
| panorama | `structure:tileMax` / `tileRms` / `subject:centroid` / `subject:radius` | 程序化噪声（批次 5 §7.2） |
| focused-star | `structure:tileMax` | 程序化噪声 |
| planet-focus | `structure:tileMax` / `tileRms` / `subject:centroid` / `coverage` | 手性镜像（批次 5 §7.3） |

新增第 10 项：

| 状态 | 越界 | Three | Babylon | 归类 |
|---|---|---:|---:|---|
| planet-focus | `toneBand:highlight` | 0.0504 | 0.0095 | **提升导致的刻意背离** |

`toneBand:highlight` 量的是亮度 ≥ 0.85 的像素占比。Three 的 0.0504 之所以那么高，
是因为**它自己的恒星圆面也是一团烧白的光**（见 `three-parity-v1-planet-focus.png`）。
要把这一项拉回容差，就得让 Babylon 重新把圆面烧白 —— 那正是本批任务点名禁止的
「纯白团」。

这不是猜测，是量过的。按**圆面面积**均匀采样（μ = √(1−r²)，r² 均匀）再过一遍
显示端色调曲线：

| | 落在 ≥ 0.85 显示亮度的样本 | 显示亮度跨度 |
|---|---:|---:|
| 提升前 | **0.9654** | 0.4431 |
| 提升后 | **0.5339** | 0.9763 |

中间试过一版把对比曲线从 1.85 softened 到 1.62：`highlight` 只从 0.0095 升到
0.0138（仍然越界），而 `detailDensity` 从 1.68× 掉到 1.39×。也试过加一个
核心热斑（`1 + 0.55·μ⁵`）：`highlight` 只到 0.0139，却把星斑的显示端对比度
从 0.55 打到 0.35 —— 星斑读不出来了。两版都回退了。

**这一项已经被单测钉住**，不是靠这份文档的说明活着：
`starSurfaceUplift.test.ts` 的 `never lets the whole disc clip to display white`
把上面两行数写进注释当反例，并断言按面积采样的过曝比例 < 0.70、显示亮度跨度 > 0.80。

**没有任何一项越界是靠放宽容差消掉的**，本批**新增**了 5 条门禁：
- 圆面不得整体过曝（上）；
- 星斑本影的显示端对比度 > 0.55；
- 米粒明暗的显示端对比度 > 0.09（恢复批次实测 0.0153）；
- 分档不得删任何一个效果类别（14 项逐档断言）；
- 分级不得改动 exposure 与 bloomThreshold。

## 8. `compare:stellar-baselines` 为什么红（与本批无关）

```
render baseline: panorama camera angle drift exceeded tolerance
```

| | alpha | beta |

所以这条同引擎漂移比对从那时起就一直是红的。

本批**没有动过开场机位**（`arcRotateFromYawPitch(THREE_PANORAMA_YAW, THREE_PANORAMA_PITCH)`
一行未改）。正确的收尾是由基线的所有者在批次 5 的机位上重采一次
`babylon-stellar-v1.json` —— **重新冻结一份参考基线是一个需要被批准的决定，
不该由一个为了让门禁变绿的批次顺手做掉**，所以这里只报告，不改。
