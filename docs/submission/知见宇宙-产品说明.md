# 知见宇宙：让知乎收藏与创作，长成一张可以探索的认知星图

**项目名称：**知见宇宙（Mindverse）

**在线体验：**https://mindverse.chouheiwa.top

**项目类型：**基于知乎内容与大模型的个人知识探索工具

一个人可能同时收藏过城市规划、游戏设计和算法分析。它们分散在不同收藏夹里，标题也各不相同。可这些内容背后，可能藏着同一种好奇：规则怎样影响行为？复杂系统怎样运行？

知见宇宙想让这样的联系变得可见。

用户授权自己的知乎账号后，产品读取接口允许范围内的收藏与创作内容，将其中的概念组织成三维星图。用户可以从星群进入恒星，再找到具体的知乎问题、回答或文章，沿原始链接继续阅读。尚未授权的用户，也能通过现场选择兴趣方向生成一份基于公开内容的体验宇宙。

## 一、为什么做这个产品

收藏让内容留下来，却不一定让内容之间的关系留下来。

随着阅读和创作不断积累，用户会遇到三个具体问题：记得自己看过某个观点，却找不到当时的内容；收藏夹越建越多，跨领域的联系越来越难发现；过去很在意的问题，后来是否继续追问，很难从列表中看出来。

知见宇宙把这些零散足迹组织成可探索的空间。它既保留主题之间的关联，也保留回到原文的路径。用户可以先看自己反复接近哪些概念，再检查这些概念由哪些具体内容支撑。

产品希望服务于有持续知乎阅读、收藏或创作习惯的人，尤其是需要积累资料的学生、研究型读者和内容创作者。对尚未形成大量个人足迹的用户，游客入口提供了开始探索的方式。

## 二、用户怎样完成一次核心体验

### 1. 带着自己的内容进入

用户通过知乎账号完成授权。服务端在开放接口和调用额度允许的范围内读取其创作、收藏等数据，包括内容标题、摘要及可获取的关系信息。

用户也可以进入游客模式，选择 6～12 个兴趣方向。产品通过知乎搜索获取相关公开内容，再使用同一套分析流程生成星图。页面会区分真实个人数据与现场选择的公开样本，不将游客结果描述为用户的历史。

内容不足时，产品会明确提示用户调整入口或选择，不用虚构内容填满宇宙。

### 2. 看见宇宙逐渐形成

生成过程分成“拾起微光”“寻找引力”“星群成形”三幕。星尘随真实处理阶段逐渐聚拢，用户可以移动鼠标带动星场，也可以轻触激起光波。

画面下方保留真实的服务端处理状态。交互只改变等待时的视觉反馈，不改变分析结果，也不伪造完成进度。已有结果很快返回时，产品不会为了播放完整动画而延迟进入。

### 3. 从概念走到问题，再回到证据

宇宙中的不同对象承担不同用途：

| 对象 | 对应内容 | 用户能做什么 |
|---|---|---|
| 星群 | 经常一起出现的一组概念 | 观察自己的主题结构与跨领域联系 |
| 恒星 | 从个人内容中抽取的概念 | 查看支撑这个概念的内容线索 |
| 行星 | 能确认身份的真实知乎问题 | 进入问题，继续查看相关回答 |
| 卫星 | 具体回答 | 辨认已有关系，沿链接阅读原文 |
| 探测器 | 文章等独立材料 | 检查材料，并打开对应原文 |

产品支持从宇宙全景逐步进入更具体的对象。文章作为概念旁的独立材料存在，不会仅凭视觉邻近就被解释为某个问题的答案。

这套交互希望建立一条连续路径：发现主题、找到问题、查看证据、继续阅读。

### 4. 决定哪些内容可以分享

用户需要逐项选择想公开的问题，并先确认服务端生成的分享预览，再创建链接。公开视图不包含整张私人认知星图，也不公开个人收藏与创作绑定。

用户可以撤销分享，或使用“立即删除我的宇宙”清除当前会话数据及对应的私人分析缓存。

## 三、技术方案：理解内容，再计算关系

项目采用 Go 服务端、React 与 TypeScript 前端，以及 Babylon.js 三维呈现。服务端负责知乎接入、概念分析、图计算、缓存与分享管理；前端负责宇宙探索和证据展示。

完整流程可以概括为：

**知乎授权内容或游客公开样本 → 内容身份整理与过滤 → 大模型抽取概念 → 概念关系图 → 本地社区发现与布局 → 三维宇宙 → 原文回链。**

### 大模型负责概念理解与命名

当前接入 MiniMax-M3，通过兼容 Chat Completions 的接口调用。模型根据标题、摘要、收藏夹名称等输入抽取概念，并参与同义概念归并和星群命名。

抽取维度除了领域，还包括方法、对象与好奇的方向。例如，两条分属不同领域的内容，可能共同涉及“底层原理”或“权衡取舍”。这样的概念让跨领域联系有机会进入后续计算。

模型提炼的结果是一种可供探索的内容组织方式，不作为用户人格、立场或专业能力的判定。

### 图算法负责关系与空间结构

服务端构建内容与概念的二部图，将共现关系投影到概念之间，通过社区发现得到星群，再计算空间布局及时间特征。已有时间数据也用于观察主题的持续性、集中出现和长期未活跃情况。

聚类与布局在本地计算。大模型不会直接编造一整张宇宙及其关系。

### 通过增量分析控制重复调用

同一用户的内容会按稳定身份和实际分析输入生成指纹。新增、发生变化或上次未成功分析的条目才需要重新抽取概念；已有标签和未变化星群的名字可以复用。

私人缓存按服务端确认的用户身份隔离，保存指纹、概念标签和星群名。已有概念词表也会参与新增内容的分析，减少同一个概念被反复起不同名字的问题。

固定 mock 示例使用离线标注与结果缓存，即使服务器配置了模型，也不会因为打开示例而调用大模型。

当前实现的增量范围是模型分析。知乎数据采集仍采用有限分页，图聚类与布局仍基于当前可用语料整体计算；采集游标和稳定布局的局部更新属于后续工作。

## 四、使用了哪些知乎开放能力

| 知乎能力 | 在产品中的用途 |
|---|---|
| 知乎 OAuth 与授权用户基础信息 | 建立真实用户身份与授权会话 |
| 授权用户创作、收藏及收藏夹数据 | 提供个人星图的内容来源与关系线索 |
| 知乎搜索 | 将游客选择的兴趣方向展开成公开内容 |
| 问题下的回答摘要 | 在已有问题周围补充可回链的公开回答材料 |
| 开放平台额度查询 | 在真实数据采集前辅助判断剩余调用能力 |

公共回答采用本地缓存，减少重复请求。别人的回答不参与个人概念抽取与星群聚类，不会因为补充了公共回答，就改写用户自己的兴趣结构。

## 五、与知乎社区的契合点

知乎的价值既在于问题与回答，也在于人们围绕同一个问题留下的不同经验和解释。知见宇宙利用这些内容已经存在的结构，帮助用户重新找到值得追问的问题。

对读者而言，星图提供了一种重新进入旧收藏的方式。对创作者而言，它可以成为整理长期关注主题、寻找下一次表达线索的起点。对社区而言，探索最终回到具体问题、回答和文章的原始页面，继续阅读和讨论的入口仍在知乎。

产品不把收藏等同于认同，不替用户归纳未经证据支持的态度，也不把模型生成的解释替代为原作者的观点。

## 六、隐私、数据边界与当前完成度

项目已部署可公开访问的 Demo，线上使用真实用户数据模式，并已接入 MiniMax-M3。游客生成、交互式等待、概念增量缓存和可撤销分享均有对应实现。

原文、标题、OAuth token 和完整私人宇宙不进入私人分析缓存。服务端持久化的是内容指纹、概念标签与星群名；公开分享只保存用户明确选中的允许公开字段。用户删除宇宙时，对应私人分析缓存也会清除，删除前已启动的任务不能将其重新写回。

数据缺失会如实呈现：摘要不会被当作全文；没有可靠身份的内容不会被随意映射为真实问题；缺失时间不会被补成看似完整的历史。个人数据读取受授权范围、接口分页与每日额度约束，当前版本不声称取得了用户的全部知乎历史。

后续将优先改进真实数据同步、局部布局稳定性，以及空数据和接口额度不足时的体验，让这张宇宙能够随着用户持续积累内容而更新。
