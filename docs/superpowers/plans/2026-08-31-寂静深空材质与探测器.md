# 寂静深空材质与文章探测器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复生产构建 3D 黑屏，并交付以深黑负空间为主、具备可解释问题星球材质和可主动检查文章探测器的电影级知识宇宙。

**Architecture:** `UniverseView` 作为唯一语义导航状态源，`Renderer` 只执行渲染命令并回报事件；星球业务指标先经纯函数归一化，再作为 InstancedMesh 属性进入 Shader；文章探测器由共享几何/材质组成三级 LOD，近景只保留一个高细节实例。生产可用性由 Playwright 针对 Go 提供的真实构建产物验证，并提供完整文本降级路径。

**Tech Stack:** React 19、TypeScript 6、Three.js 0.185、postprocessing、Vite 8/Rolldown、Vitest、Testing Library、Playwright、Go 静态服务器。

**Design spec:** `docs/superpowers/specs/2026-08-31-寂静深空材质与探测器-design.md`

- [ ] **Step 1: 在实现前写 ready 与三类故障注入失败测试**

扩展 mock callback：

```ts
export interface RendererCallbacks {
  // existing callbacks
  onRenderReady?: () => void
  onRenderError?: (cause: Error) => void

```

Vitest 断言：唯一 reducer state 初始 `renderPhase === 'loading'`；`onRenderReady()` 后为 `ready`；已有 Universe 数据时动态 `import()` reject 或触发 `onRenderError()` 都把 `exploration` 设为 `render-fallback`、`renderPhase` 设为 `failed`，显示“3D 星图暂时不可用”和“重试 3D”。

Playwright 在任何实现之前增加并跑红：Renderer chunk 首次请求 503、WebGL context 创建失败、`?e2eShaderFail=once`。chunk 拦截只失败第一次；“重试 3D”对模块加载失败执行整页 reload，避免浏览器缓存 rejected module，第二次请求必须 2xx 并最终 ready。WebGL/Shader 重试可以在同页重建 Renderer。

- [ ] **Step 3: 实现只触发一次的首帧 ready**

在 `composer.render()` 成功返回后调用：

```ts
if (!this.renderReady) {
  this.renderReady = true
  this.cb.onRenderReady?.()
}
```

frame 中捕获不可恢复的渲染错误，停止 RAF 并调用 `onRenderError`；context lost 也进入可恢复错误状态。`mountRenderer().catch(...)` 必须在 Universe 已存在时进入同一个 render-fallback，而不是只写普通 error 字符串。`destroy()` 保证迟到回调不再发出。

本任务同时实现 E2E-only Shader one-shot hook：仅当 `VITE_E2E_DIAGNOSTICS=1` 且 URL 含 `e2eShaderFail=once` 时，首次进入先在 sessionStorage 写入 `mindverse:e2e-shader-failed=1` 再抛错；同页 remount 看到标记后放行；Renderer ready 后删除标记。普通生产构建完全裁掉该分支，避免每次 remount 重复失败。

Renderer 构造使用 `ResourceScope.defer(dispose)` 分阶段登记 WebGLRenderer、nebula targets、各 GL layer、composer、事件监听器和 RAF；任一步抛错立即逆序清理。`dispose()` 幂等。测试分别在 WebGL、nebula、shader、composer 阶段抛错并断言已创建资源只释放一次。

`makeStars/makeDust/makeRings/makeOverlay3D/Labels` 各自在函数/构造器内部使用局部 ResourceScope：几何、材质或监听器一创建就登记，成功返回时转交给幂等 dispose，构造中途失败则立即逆序清理。`resourceLifecycle.test.ts` 对每个工厂注入“创建第 N 个资源后抛错”，断言 scope 清空且重复 dispose 不增加调用数。`makeNebula/makeBodies/makeProbe` 分别在 Task 4/5/7 按同一模式实现，不能依赖 Renderer 外层补救。

- [ ] **Step 4: 实现完整文本降级与重试**

`explorationState.ts` 导出一个 reducer 根状态：

```ts
interface UniverseUiState {
  exploration: ExplorationState
  renderPhase: 'loading' | 'ready' | 'failed'
}
type RenderFallback = { kind: 'render-fallback'; message: string; recovery: 'reload' | 'remount' }
```

`RenderFallback` 从 `UniverseIndex` 输出“星群 → 恒星 → 问题 → 回答/文章原文”，所有原文使用真实 URL。UniverseView 只使用这个 reducer，不再创建 renderState/ready/error 布尔状态。动态 import 失败 dispatch `recovery:'reload'`，其余可重建失败 dispatch `recovery:'remount'`；按钮行为从字段判断，不从错误文本猜测。
