# Babylon.js Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and objectively gate a Babylon.js WebGL2 vertical slice that renders real question planets, crosses one planet surface into evidence-safe answer strata, opens a React answer evidence panel, and never initializes Three and Babylon in the same build.

**Architecture:** Keep React as the discrete business-state owner and introduce an engine-neutral `MindverseRenderer` contract. Vite resolves a virtual renderer module to either the existing Three renderer or the Babylon slice at build time, so each artifact contains one renderer implementation. A pure `strata-layout.v1` domain model supplies deterministic, evidence-gated scene data; Babylon owns only continuous pose, rendering, picking, and transitions.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Vitest, Playwright, Babylon.js 9 WebGL2, existing Go API and `UniverseIndex` domain model.

**Scope boundary:** This plan ends at the vertical-slice gate in the approved spec. It does not remove Three from the repository or migrate the complete nebula/star/probe renderer. If the gate passes, write a second plan for the full renderer migration; if it fails, remove the Babylon product path rather than shipping two engines.

**Command convention:** Every `npm`/`npx` command runs from `frontend/`. Every `git` and `go` command runs from the repository root. Commands below state `cd frontend &&` when shown from repository root; `git add frontend/...` paths are therefore intentional.
