# 知乎精神宇宙 · 电影级视觉补齐设计

版本：v1.0　　日期：2026-08-28　　状态：待用户评审

本文是《产品与技术设计.md》第 7 章（视觉与渲染）的工程落地设计。第 7 章回答"做成什么样"，本文回答"在这个现有代码库里怎么接、按什么顺序接、接不上时怎么降级"。

---

## 1. 背景与现状

现有代码质量很高，但跑起来的视觉与 §7 的电影级愿景之间存在五处缺口：

| # | 缺口 | 现状（file:line） | §7 愿景 |
|---|---|---|---|
| 1 | 景深 | `Renderer.ts:203` 的 composer 只有 Bloom + ToneMap | §7.6：景深是"电影感最大来源"，优先级高于泛光 |
| 2 | 音频 | 全栈无 Web Audio | §7.8：点火旋律是分享传播点，"严重被低估" |
| 3 | 创世爆发 | `stars.ts:75` `mix(aStart,target,uConverge)` 是单段线性收敛 | §7.2：奇点→爆发→聚集→点火，是路演第一个高潮 |
| 4 | 虫洞穿越 | `overlay3d.ts` 是沿贝塞尔曲线流动的粒子流（动画虚线）；点虫洞只 dim 其它星 | §7.4：真传送门 + 第二相机 RT + 瞬移 + 白闪，"三分钟里最强的一击" |
| 5 | 真引力透镜 | `overlay3d.ts` `DARK_FRAG` 是画在 billboard 上的爱因斯坦环 | §7.5：后期 pass 真扭曲背景，"全场设计里最妙的一处" |

引擎（`internal/engine`）与数据契约（`types.ts`）不动——视觉补齐只动 `frontend/src/starmap/` 与 `frontend/src/ui/`。

## 2. 目标与非目标

**目标**：把这五处缺口补齐到 §7 的电影级标准，分五个 session 落地，每个 session 合并一个功能且 demo 持续变好。

**非目标**：
- 不重写 Renderer 或重建 composer 地基（策略 A：增量加 Effect，不大重构）。
- 不动后端语义引擎与数据层。
- 不引入音频/视频素材文件——音频全程程序化合成。
- 不为本次工作引入新运行时依赖（`postprocessing`、`three` 已在 `package.json`）。

## 3. 总架构原则

1. **不大重构**。`Renderer.ts:194` 的 `EffectComposer` 现为 `RenderPass + EffectPass(Bloom + ToneMap)`。景深/透镜/色差是往这个 `EffectPass` 里增量加 `Effect`；音频/创世爆发相位/虫洞相机是挂在 `Renderer` 上的独立系统。每步只动一处。
2. **命令式优先**。canvas 每帧重绘，不挂 React 重渲染上（与现有 `Renderer.ts:30` 注释一致）。
3. **数据驱动视觉**。每个视觉参数仍绑回 `Universe` 的字段（持续性→亮度、星群大小→点火音高、暗物质质量→透镜强度），不引入无解释的随机值。
4. **降级是设计的一部分**。每个功能都要能优雅退化，绝不因为视觉效果失败而阻断主流程（星图本身、证据链、分享卡必须始终可用）。

## 4. 推进策略

采用策略 A（按"视觉提升 ÷ 工作量"排序，每 session 落一个功能）：

| Session | 功能 | 选它当先的理由 |
|---|---|---|
| 1 | 景深 | 最便宜、提升最大，§7.6 点名"电影感最大来源" |
| 2 | 音频 | 程序化合成零素材，§7.8"严重被低估" |
| 3 | 创世爆发 | 第一个高潮；可在现有顶点着色器上扩展，不需 GPGPU |
| 4 | 虫洞穿越 | 最难、最核心；放第 4，等管线地基撑得住多相机/RT 再上 |
| 5 | 真引力透镜 | §7.5"全场最妙的一处"；放最后因为自定义 post Effect 依赖前面铺好的管线 |

§14.1 的"虫洞穿越 绝不能砍"是时间不够时砍什么的标准，不是建造顺序。多 session 预算下五个都会做，顺序只关乎手感和节奏。

## 5. Session 1 · 景深（DOF）

### 5.1 接入点
- 文件：`frontend/src/starmap/Renderer.ts`
- 位置：`Renderer.ts:203` 的 `EffectPass`，在 `BloomEffect` 之后、`ToneMappingEffect` 之前插入 `DepthOfFieldEffect`（`postprocessing` 库已提供）。
- 焦点来源：`Renderer` 的 `this.focus`（注视点，相机本来就看向它，`Renderer.ts:354` `camera.lookAt(this.focus)`）。

### 5.2 参数与缩放
- 焦距/光圈按 `this.R`（场景半径，`Renderer.ts:157`）缩放，不写死绝对值——后端布局尺度改了这里不用动。
- 飞进恒星系时相机收近（`targetDist` 变小），景深自然收窄，不需要专门切"恒星系模式"。
- 焦点跟随：相机注视点从全景中心 → 单颗恒星 → 单颗行星，景深焦点跟着走。

### 5.3 画质分级
- High：开。
- Medium：开，光圈稍收。
- Low：关（与 §7.9 一致）。
- 分级逻辑接现有 `reduceMotion` 之上的 GPU 检测（当前只有 `reduceMotion`，本 session 顺手加一档"画质分级"最小实现：首帧耗时 + `MAX_SAMPLES` 已有的检测）。

### 5.4 验证
- 视觉：全景时远景星群被压暗、近景恒星系时背景虚化——"看进去"而不是"贴上去"。
- 性能：60fps @ 1080p 中端集显（§7.9 预算）。DOF 在集显上是已知的较贵 pass，中端掉帧就把 Medium 光圈收窄、Low 关掉。
- 回归：现有创世收敛、拾取、模式切换行为不变。

### 5.5 降级
- `DepthOfFieldEffect` 初始化失败 → 不加，demo 退回当前 Bloom-only 状态，不阻断。

## 6. Session 2 · 音频

### 6.1 组件
- 新建 `frontend/src/starmap/audio.ts`，导出一个 `AudioEngine` 类。
- Web Audio API 程序化合成，零素材文件。

### 6.2 声音设计（全部数据驱动）
| 声音 | 合成方式 | 数据绑定 | 时机 |
|---|---|---|---|
| 底噪 | 40Hz 正弦 + 缓慢演变的失谐 pad（几个频率略偏的振荡器） | — | 进宇宙后常驻 |
| 点火 | 短促上行音（包络衰减的正弦/三角） | 频率 ∝ 星群大小 | `stars.ts` 的 `aIgnite` 时刻，逐星群触发 |
| 穿越 | 低频下潜 + 白噪爆裂 + 出口 0.4s 骤静 | | 虫洞穿越动作（Session 4 落地后挂钩，本 session 先留接口） |
| 交互 | 清脆定位音（短高频正弦） | | 点击天体 |

"点火旋律"是分享传播点：每个人的星群数量与大小不同，点火段落会奏出一段独一无二的旋律（§7.2）。

### 6.3 自动播放策略
- `AudioContext` 必须在用户首次点击后 `resume()`（浏览器策略，§7.8）。
- 落地页→宇宙页的跳转本身就是一次用户手势，进宇宙后可在首个交互内安全启动。

### 6.4 接口
- `Renderer` 增加 `RendererCallbacks`：`onIgnite?(clusterId: number, size: number)` / `onTravel?()` / `onPick?()`。
- `audio.ts` 由 `Universe.tsx` 实例化并随 `Renderer` 生命周期销毁（`disconnect()` 所有节点）。
- 穿越/交互音效在 Session 4 / 已有拾取处挂钩；本 session 先把底噪 + 点火旋律跑通。

### 6.5 降级
- `AudioContext` 不可用或 `resume()` 被拒 → 静默，绝不抛错、绝不阻断视觉。
- 用户关闭声音 → 提供 UI 开关（接现有模式条或 header）。

### 6.6 验证
- 不同星图点火段落确实不同（用 mock 的两份人格迥异数据验证）。
- `disconnect` 后无节点泄漏。

## 7. Session 3 · 创世爆发

### 7.1 现状与改法
- 现状：`stars.ts:75` `vec3 p = mix(aStart, target, uConverge)`，单段线性收敛，只有"聚集"没有"爆发"。
- 改：把 `uConverge` 的单段 ease 拆成三段时间线，全在顶点着色器里算：
  1. **爆发喷射**（0–~2s）：粒子从奇点附近朝外喷，位移沿 (aStart - 原点) 方向先增大。
  2. **引力聚集**（~2–~7s）：粒子被各星群质心吸引，塌缩回 `target`（即现有的收敛段，保留）。
  3. **点火**（已有）：`lit = (uT - aIgnite)/uIgniteMs`，点燃次序由持续性排序（`starData.ts` 已做）。
- 用一条 `uGenesisPhase` uniform（0..1 的总进度）驱动三段，`aStart` 已经是属性，加一个爆发阶段的位移即可。

### 7.2 为什么不用 GPGPU
- 粒子数只有几百到几千，顶点着色器算得动。
- §7.9 自己说"我们只有几百到几千个天体，离性能红线很远"。
- GPGPU（transform feedback / ping-pong 纹理）复杂度高、WebGL2 上 fiddly，收益不抵风险。
- 粒子就是条目本身（§7.2："粒子数 ∝ 条目数"），不另起瞬态粒子层——爆发是恒星层自己经历的相位，不是额外撒一把火星。

### 7.3 恒星表面与日冕
- 点火瞬间补表面湍流 + 日冕张开（§7.3 的 domain-warped 三维单纯形噪声 GLSL）。
- 落在 `gl/bodies.ts` 球体材质的 fragment shader 里（现在球体是 LOD 接管后的近景表示）。
- 一个数据字段驱动三处（§7.3）：`persistence` 同时驱动自发光强度、泛光阈值、日冕半径。保持这个统一。

### 7.4 落地页创世
- 落地页 `layers.ts` 是 Canvas 2D，不带创世序列——保持，落地页只要氛围底（§layers.ts:1-5 注释已说明）。
- 创世序列只服务宇宙页 `Renderer`。

### 7.5 画质分级
- High：三段全开，粒子数满。
- Medium：爆发段简化（位移幅度减半）。
- Low：粒子降至 1/4，爆发段跳过（直接收敛）。

### 7.6 验证
- 视觉：能明显看到"先喷出去、再塌回来、再一颗颗点着"三段，而不是现在的直接到位。
- 数据一致：爆发喷射的粒子数 = 条目数，颜色 = 星群色（§7.1"炫目与可解释是同一件事"）。
- 性能：爆发段是瞬时高峰，确认不超 16ms 预算。

### 7.7 降级
- 顶点着色器三段时间线编译失败 → 退回现有单段 `mix`，创世仍成立只是没爆发。

## 8. Session 4 · 虫洞穿越（4-C 混合方案）

### 8.1 方案选择：4-C
在三个候选里选 4-C（混合）：

- **4-A 真传送门**（文档原样）：第二相机渲染另一端到 RT，虫洞口圆盘采样它——靠近时真的看见对岸。瞬移穿越。最震撼但工程量最大、瞬移有硬切风险。
- **4-B 程序化隧道**：不画"看见对面"的门，穿越时冲进 shader 隧道，尽头淡出。便宜但丢掉"真门"这个震撼来源。
- **4-C 混合（采用）**：虫洞口仍采样第二相机 RT（保住"看见对面"），穿越瞬间用一段 80–120ms 程序化隧道过渡遮住瞬移硬切，再在对岸展开 + 弹证据面板。色差峰值 + 白闪照 §7.4 加。

选 4-C 的理由：既保住 §7.4 最在意的"看见对面"+"穿越"两个点，又用隧道过渡掩盖瞬移硬切——隧道遮瞬移是行业藏切换的标准手法。

### 8.2 组件
- `frontend/src/starmap/gl/wormhole.ts`（新文件）：虫洞口圆盘 mesh + 第二相机 + RT + 径向扭曲 shader。
- `frontend/src/starmap/gl/tunnel.ts`（新文件）：程序化隧道过渡（穿越瞬间的全屏 pass）。
- `overlay3d.ts` 的粒子流保留作为"平时可见的虫洞示意"，穿越时由 tunnel + portal 接管。

### 8.3 数据流
1. 引擎产出的 `Universe.wormholes[]`（`types.ts` `Wormhole`，含 `a/b` 星群 id、`z`、`ev` 证据）驱动虫洞口位置（锚定两星群质心 `Cluster.c`）。
2. 虫洞模式（`mode === 'worm'`，`ModeBar`）激活当前虫洞 `wormIdx`：虫洞口 mesh 显形，第二相机看向对岸星群质心，渲染到 RT。
3. 靠近时径向扭曲 shader 强度随相机-虫洞口距离上升。
4. 穿越：相机加速冲入 → 80–120ms 隧道过渡（遮瞬移）→ 主相机瞬移至对岸 → 色差峰值 + 80ms 白闪 → 出口星群展开 → 弹证据面板（`Panel`/`InfoPanel` 现有结构）。

### 8.4 相机时序
- 用命令式时间线编排（不引入 GSAP——现有 `Renderer` 用 `requestAnimationFrame` + 时间衰减，保持一致），在 `Renderer.frame` 里加一段穿越状态机：`idle → approaching → traveling → arriving`。
- 穿越瞬间 `onTravel()` 回调触发 Session 2 的穿越音效。

### 8.5 画质分级
- 所有档位保留虫洞穿越（§7.9："所有档位保留……虫洞穿越"）。
- Low 档：RT 分辨率降至 1/2，隧道过渡缩短，径向扭曲简化。

### 8.6 验证
- 路演三分钟里 1:20–1:35 的穿越段成立（§13 脚本）。
- 穿越"能点回原文"：对岸弹出证据面板，6 条收藏可点（§5.4 显性虫洞）。
- 第二相机 RT 不拖垮帧率。

### 8.7 降级
- RT 分配失败或第二相机初始化失败 → 退到 4-B（纯程序化隧道，无真门）。
- 隧道 shader 也失败 → 退到现有粒子流 + 硬切瞬移（当前状态），证据面板仍弹。

## 9. Session 5 · 真引力透镜

### 9.1 现状与改法
- 现状：`overlay3d.ts` `DARK_FRAG` 是画在 billboard 上的爱因斯坦环——"画出来的环"，不是"真扭曲了背景"。
- 改：写一个自定义 `postprocessing` 的 `Effect`（继承 `Effect`），在屏幕空间做径向 UV 位移采样场景纹理。

### 9.2 数据流
1. 暗物质列表 `Universe.dark[]`（`types.ts` `Dark`，含概念、`f` 收藏数=质量、位置由对应 `Star.p`）。
2. 每帧 `Renderer` 把各暗物质的屏幕投影位置 + 质量（`f`）写进一张小数据纹理（RGBA：`xy` 屏幕坐标、`z` 质量、`w` 作用半径）。
3. 自定义 `Effect` 的 fragment 采样场景纹理时，按数据纹理里每个暗物质做径向位移叠加。

### 9.3 管线位置
- 按文档 §7.6 管线：`Bloom → GravitationalLens → DOF → ChromaticAberration → Vignette → Noise`。
- 透镜在 Bloom 之后、DOF 之前。
- 保留现有 billboard 爱因斯坦环但压到极淡（`overlay3d.ts` `uEmphasis` 已有，`Renderer.ts:411` 全景压到 0.14），主要靠真扭曲——§7.5 就是"不发光，仅以引力透镜扭曲背景"。

### 9.4 画质分级
- High：真扭曲全开。
- Medium：作用半径减半、位移幅度减半。
- Low：关真扭曲，只留极淡 billboard 环。

### 9.5 验证
- 视觉：背景星星在暗物质处确实被弯，但看不到弯它的东西——§7.5"隐喻、物理与数据三者统一"。
- 多个暗物质叠加时位移不撕裂（叠加方式需在 shader 里做软上限）。

### 9.6 降级
- 自定义 `Effect` 编译失败 → 退回现有 billboard 环，语义不丢（只是不是"真扭曲"）。

## 10. 后期管线最终形态

五个 session 落完后，`Renderer.ts` 的 composer 管线应为（按 §7.6）：

```
RenderPass(scene, camera)
  → EffectPass(
      BloomEffect(仅恒星层, threshold ∝ persistence)   [已有]
      → GravitationalLensEffect(自定义, 暗物质)        [Session 5]
      → DepthOfFieldEffect(焦点 = focus)              [Session 1]
      → ChromaticAberrationEffect(0.0008, 穿越时 0.02) [Session 4]
      → ToneMappingEffect(NEUTRAL)                    [已有]
    )
```

> 注：现有 `Renderer.ts:208` 用 `mipmapBlur` Bloom + `NEUTRAL` tone map，刻意不用 ACES（颜色是数据，§Renderer.ts:26）。这条原则贯穿所有新增 Effect——不染歪数据色。

**Vignette / 颗粒不进 post 管线**：`theme.css:96-103` 已有 CSS 层的 `.vignette`（径向暗角）与 `.grain`（SVG 噪声），DOM 层就够且零额外开销，post 层不再重复加 `VignetteEffect`/`NoiseEffect`，省一个 pass。后期管线唯一额外加的低成本 Effect 是 `ChromaticAberrationEffect`，随 Session 4（穿越需要色差峰值）一起加。

## 11. 技术决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 创世爆发用不用 GPGPU | 不用，顶点着色器 | 粒子数几百到几千，§7.9 自述离性能红线远；GPGPU 复杂度不抵风险 |
| 虫洞穿越实现路线 | 4-C 混合 | 保住"看见对面"+"穿越"，隧道过渡遮瞬移硬切 |
| 音频素材 | 程序化合成 | 零素材、确定性、音高可绑数据、符合 48h 无资产管线现实 |
| 镜头编排用不用 GSAP | 不用，命令式 rAF | 与现有 `Renderer` 一致，不引新依赖 |
| 透镜用真 post 还是 billboard | 真 post + 极淡 billboard | §7.5 明确要真扭曲背景；billboard 留作可见的极淡环 |
| tone mapping | 保持 NEUTRAL | 颜色是数据（琥珀=收藏、蓝白=创作），ACES 会染歪 |

## 12. 风险与降级总表

| 风险 | 降级 |
|---|---|
| 集显跑不动 DOF/透镜 | 画质分级：Medium 收参数、Low 关掉；§7.9 所有档位保留虫洞穿越与恒星表面 |
| 第二相机 RT 拖垮帧率 | RT 降至 1/2；再不行退 4-B 隧道、退现有粒子流 |
| 自定义 post Effect 编译失败 | 退 billboard 环（透镜）/现有单段收敛（创世）/不加（DOF） |
| AudioContext 被浏览器拒绝 | 静默，不阻断视觉 |
| 顶点着色器三段时间线太复杂 | 退单段 mix，创世仍成立 |
| 任意视觉失败 | 星图本身、证据链、分享卡必须始终可用——视觉是锦上添花，不是承重墙 |

## 13. 验收标准

每个 session 落地后应满足：
