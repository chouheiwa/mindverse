# 知见宇宙 Mindverse · 融合产品需求与设计

版本：v1.0　　日期：2026-08-30　　状态：产品方向已确认，待组内评估

> 产品名：**知见宇宙 Mindverse**<br>
> 副标题：**穿越观点的时间，校准自己的判断**<br>
> 参赛赛道：**📚 知识炼金场**

---

## 1. 文档目的

本文档将三个原始构思融合为一个产品：

- 「知乎精神宇宙」：基于 OAuth 真实足迹构建个人认知空间；
- 「答案纪年」：呈现一个知乎问题的公共认知如何随时间演化；
- 「观点棱镜」：拆解同期答案的立场、证据、前提、价值与适用边界。

文档用于组内产品、设计和技术评估，不以 48 小时、比赛现场或最小可行产品为边界，描述产品最终应当成为什么。

---

## 2. 一句话定义

**知见宇宙是一个基于用户真实知乎足迹、持续维护个人认知宇宙的深度知识服务：用户可以进入任意问题行星，沿答案纪年穿越公共观点的历史地层，再用观点棱镜分解立场背后的证据、前提与边界，最终形成会被新证据持续更新的个人判断。**

---

## 3. 产品母题

很多人在知乎上累积了大量收藏、关注和创作，却仍难以回答四个问题：

1. 我究竟长期在关心什么？
2. 我看到的这些说法，在历史上是怎样形成的？
3. 人们为什么面对相同问题仍得出不同结论？
4. 我现在真正相信什么，什么证据可能让我改变？

知见宇宙不是用 AI 代替用户下结论，而是把「阅读足迹→问题结构→历史演化→分歧来源→个人判断→新证据更新」变成一条可见、可验证、可持续的认知链路。

---

## 4. 为什么必须是知乎

本产品依赖知乎特有的四类资产：

| 知乎资产 | 产品作用 |
|---|---|
| 真实问题 | 构成问题行星，为纪年和棱镜提供可验证的分析边界 |
| 多年答案沉淀 | 构成公共认知地层，让观点的出现、兴衰与转折可被看见 |
| 专业与经验性表达 | 为观点棱镜提供多元立场、证据、隐藏前提和适用边界 |
| 个人关注与创作足迹 | 使产品从通用知识图谱变成个人认知系统 |

知乎开放平台的 OAuth、关注流、关注关系、知乎搜索、全网搜索和热榜能力，分别对应个人宇宙、公共问题建模、外部证据补充和认知事件发现。

### 4.1 产品成立的数据前置条件

以下不是普通技术优化，而是对应产品能力成立的前置条件：

| 产品能力 | 必要数据条件 | 条件不满足时的合法降级 |
|---|---|---|
| 长期认知账户 | 平台提供稳定、不可变的授权用户标识 | 仅保留本次会话/用户手动导出，不声称可跨会话找回认知档案 |
| 问题级棱镜 | 可获得足量、可追溯、可确认属于同一问题的答案样本 | 标记为「代表性样本观测」，不声称覆盖该问题全部观点 |
| 历史地层 | 至少有可靠的首次发表时间；若要宣称历史份额迁移，还需历史快照/历史互动值 | 仅展示「当前仍可验证样本的发表年代分布」，显示幸存者偏差警示 |
| 公共认知变化 | 按固定口径定期生成的问题快照 | 仅描述观点「何时发表」，不描述「当时是否主流」 |

任何界面文案都必须根据当前数据等级选择准确口径，不得用搜索到的当前幸存样本反推「当年社区共识」。

### 4.2 初始数据质量门槛

以下是首版产品质量门槛，后续可依评估集收紧，不得为了让界面「有结果」而自动放宽：

- 问题行星：必须获得真实 question_id、标题和原页 URL；
- 棱镜分光：至少 8 篇独立答案、6 名独立作者；离散光谱的每束至少由 2 名独立作者支持，否则合并或改用连续光谱；
- 回溯地层：至少 12 篇独立答案，首发时间跨越至少 3 个日历年；每个可见地层至少 3 篇答案、3 名作者；
- 快照迁移：至少 3 个同口径快照，且前后参与比较的每个时点至少 8 篇答案、6 名作者；
- 转折声称：除满足样本量外，至少有 2 条互相独立的原文证据支持证据基础或讨论框架确已变化。

所有阈值与实际样本数在分析中可见；未达门槛时展示原始内容和「数据不足」，不生成高层结论。

核心价值是将用户的零散阅读转化为可理解、可校准、可持续更新并可再次表达的个人认知系统，与「让知识被理解、吸收和再次创造」直接一致。

## 6. 目标用户与场景

### 6.1 核心用户

- 长期使用知乎，但收藏和关注逐渐失去结构的学生与职场新人；
- 正在进入一个新专业、行业或复杂议题的知识探索者；
- 希望把阅读转化为自己判断和知乎创作的用户；
- 愿意回顾并修正自己认知的深度内容消费者。

### 6.2 高价值场景

1. 我收藏了很多内容，想知道自己真正长期关心什么。
2. 我想理解一个复杂问题，但高赞答案互相矛盾。
3. 我想知道当前主流看法是否一直如此，又因为什么发生转折。
4. 我想确认自己站在哪里，但不想被粗暴地归类。
5. 我想知道过去的判断是否已被新证据动摇。
6. 我准备在知乎回答或写文章，需要看清现有观点与真正的表达空白。

## 7. 核心体验闭环

1. **OAuth 建立宇宙**：读取授权范围内的真实足迹，识别长期问题、阶段兴趣和跨领域关联。
2. **进入概念恒星**：从宇宙全景进入某个长期概念恒星系。
3. **发现问题行星**：与用户授权数据已建立可观测关联的真实知乎问题优先成为行星，公共搜索补入高认知价值问题。
4. **观察个人轨道**：查看收藏、关注、创作和文章探测器如何围绕该问题形成轨迹。
5. **向下钻探纪年**：查看观点沉积与可验证转折；只有连续历史快照才展示份额迁移和少数观点兴起。
6. **对地层启动棱镜**：对当前地表或历史切片分光，理解分歧背后的结论、证据、前提、价值、边界与风险。
7. **定位并校准自己**：系统根据 OAuth 足迹做可解释推断，用户逐项确认、调整、删除或保持未知。
8. **形成观点晶体**：记录当前判断、证据、成立条件、保留问题与可能改变判断的新证据。
9. **持续观测**：用户主动加入观测清单，系统仅在发生有解释价值的变化时介入。
10. **回到知乎表达**：用户将阅读和判断转化为回答或文章，新创作作为探测器重新进入宇宙。

## 8. 天体语义系统

| 天体/现象 | 产品含义 | 与现有 mindverse 的关系 |
|---|---|---|
| 星群 | 大型知识领域 | 保留现有 `Cluster` |
| 恒星 | 用户长期关注的核心概念 | 保留现有 `Star` |
| 问题行星 | 一个真实存在的知乎主问题 | 在 `Star` 与内容之间新增的核心层 |
| 行星环 | 与主问题相关但未被强行合并的真实问题 | 新增 |
| 答案卫星 | 天然隶属于某个问题的具体答案 | 由现有「内容行星」语义升级而来 |
| 文章探测器 | 可跨越多个问题的长文 | 由现有文章类 `Evidence` 升级而来 |
| 探测器航迹 | 文章与多个问题的语义关联 | 新增 |
| 地质层 | 问题在某个时期沉积的答案与观点结构 | 来自答案纪年 |
| 认知地震 | 主流立场、证据基础或问题框架的显著转折 | 来自答案纪年 |
| 棱镜光谱 | 某个时间切片中的判断结构 | 来自观点棱镜 |
| 观点晶体 | 用户确认后的有条件判断 | 新增 |

### 8.1 文章探测器的视觉规则

文章不强行隶属于某个问题。一篇文章仅保存一份内容实体，通过多条关联作为论点、证据、反例或背景经过多颗问题行星。

- 远景：仅显示带方向的微小光体和航迹；
- 进入恒星系：展开为程序化低多边形 3D 探测器；
- 点击：展示文章摘要、观点切片、途经问题和原文入口；
- 用户原创 `created`：以暖色核心或尾焰区分；
- 用户收藏 `collected`：以冷色核心区分；
- 公共发现 `public_discovered`：使用不暗示个人关系的中性光体；
- 外部证据：位于独立证据旁轨，不复用文章探测器的个人关系色。

上述是数据关系而非装饰配色；任何中性公共内容都不得因历史 `Own=false` 而被展示为「我收藏的」。

## 9. 真实问题行星模型

### 9.1 原则

每颗问题行星必须对应一个真实存在、可回到知乎的问题。AI 不得凭空创建「母问题」并把多个不同问题的答案混成一条虚假历史。

真实问题以知乎问题 ID 作为全局唯一身份，不属于任何单一概念恒星。一个问题可以通过 `ConceptQuestionEdge` 关联多个公共概念，并通过 `UserStarQuestionBinding` 同时出现在某个用户的多个恒星系；它的纪年、棱镜、观点晶体和观测规则始终引用同一个全局问题实体，不生成副本。

### 9.2 生成通道

- **个人通道**：从 OAuth 内容中提取问题 ID，优先构建用户已收藏、创作或关注相关内容的行星；
- **公共通道**：仅从已由公共内容证明的 `Concept`，或用户预览确认后的脱敏查询扩展知乎搜索，补入高价值但尚未与用户授权数据建立关联的问题；`PrivateConcept` 不自动进入搜索。

### 9.3 主问题与行星环

- 一个真实问题作为行星主体；
- 相关但不同的真实问题作为行星环；
- 行星环中的每个相关问题仍是拥有独立问题 ID 的 `QuestionPlanet`；
- 点击行星环是导航到另一颗真实问题行星，不是替换当前行星的 canonical question；
- 相关性仅作为可被用户纠正的 `RelatedQuestionEdge`，不共享地层、棱镜统计或个人晶体；
- 当相似度、语义包含或数据边界无法可靠判定时，保留为独立行星。

### 9.4 重要度信号

行星优先级由个人关联和公共认知价值联合决定，包括：

- 用户是否收藏、回答、写过相关文章或关注相关创作者/话题；
- 问题的活跃时间跨度；
- 是否出现过明显观点转折；
- 当前是否仍有新回答与新证据；
- 是否连接用户宇宙中的多个概念恒星。

### 9.5 查询外发边界

- 只有已经由公共知乎内容独立证明存在的 `Concept` 和真实 `question_id` 可自动用于知乎/全网搜索；
- `PrivateConcept`、收藏夹原名、用户自述、私人晶体文本不得直接发送到任何外部搜索服务；
- 私人概念只能先在本地/租户隔离环境中映射到经过脱敏的公共问题或公共概念，或由用户显式发起并预览实际外发查询；
- 敏感领域默认禁止全网扩展，即使用户开启个人分析，也需对查询外发单独同意；
- 查询日志不记录可反推私人标签的原始搜索词。

## 10. 问题行星的三种观察模式

### 10.1 个人轨道

回答：「我与这个问题发生过什么关系？」

展示：

- 首次和最近一次可观测关联，并分别标明是收藏、创作、关注还是产品内校准；
- 用户收藏和创作的答案卫星；
- 经过该问题的文章探测器；
- 用户关注的相关创作者；
- 历次观点晶体；
- 只收藏但尚未形成判断的「暗物质」。

### 10.2 地质钻探（答案纪年）

回答：「知乎对这个问题的认识如何变化？」

纪年的口径随证据等级分为两档：

- **回溯观测**：依据当前仍可访问内容容器的 `published_at` 排列「当前版本内容」，必须常驻显示「不代表当年观点文本或社区份额」的版本时序与幸存者偏差提示；
- **快照纪年**：只有系统按固定口径长期保存过问题快照后，才可比较可观察样本在各快照时点的份额、排名和迁移。

每条内容必须分别保存 `published_at`、`updated_at` 与 `observed_at`，每个观点单元记录 `claim_first_observed_at` 和 `source_version_observed_at`。禁止用编辑时间替代首次发表时间，也禁止在没有历史正文版本的情况下将当前 `PublicClaim` 放回内容首发年份并声称它当时已经存在。

核心对象：

- `TimeStratum`：有足够证据的时间切片；
- `TurningPoint`：连续快照中的可观察份额变化，或回溯样本中有明确来源支持的证据基础/讨论框架变化；
- `MinorityRise`：在连续快照中，某观点的可观察份额持续增长；
- `SupersededClaim`：较早发表且有后续证据修正的判断，不声称它曾经流行；
- `FossilClaim`：只在连续快照或独立历史证据证明其曾广泛存在时启用；
- `PersistentFault`：长期存在且未被新证据消解的分歧。

时间切片必须由内容密度和转折信号联合决定，不得为了形成均匀地层而虚构年度分布。

答案与文章始终分轨：文章可在地层旁轨提供系统论述、证据或反例，但不直接计入答案数量、回答者份额或社区主流比例。

### 10.3 棱镜分光（观点棱镜）

回答：「同处一个时代，人们为什么仍得出不同结论？」

棱镜可对当前地表或任意历史地层启动。系统先判断分歧结构类型：离散结构时聚合为 2–5 束主要光谱，连续结构时不设定阵营数量，而展示多轴分布。结构判断必须展示置信度并允许用户反馈。

每束光谱包含：

- 核心判断；
- 事实与经验依据；
- 隐藏前提；
- 价值优先级；
- 适用人群和成立条件；
- 失效边界和主要反例；
- 代表性原回答或文章段落。

用户可以旋转棱镜，在结论、证据、前提、价值、边界和风险六个比较轴之间切换。

光谱的份额与主流判断不按 `PublicClaim` 数量投票。统计口径以独立内容和独立作者为基础，文章只作为旁轨论证材料；用户可以进入观点单元详情，但拆分更细的长文不得因此获得更高统计权重。

## 11. 个人位置推断与校准

### 11.1 原则

- OAuth 行为推断为主，用户校准为辅；
- 系统不宣布「用户属于某派」，而是逐轴推断个人光谱；
- 每项推断必须展示来源、理由、反例和置信度；
- 用户可以确认、调整、删除依据或声明尚未形成判断；
- 未经用户确认的推断不得写入永久观点晶体。

### 11.2 证据强度建议

从强到弱：

1. 用户显式确认的个人判断；
2. 用户回答中的完整论述；
3. 用户文章中与该问题相关的观点段落；
4. 持续收藏的同类内容（仅视为关注信号，不视为认同）；
5. 关注相关创作者和话题；
6. 平台未来若明确开放的其他行为信号。

收藏只能说明用户认为内容值得保留，不能自动等价为认同。

当前可用于推断的已验证信号仅包括：用户收藏、用户创作、收藏夹语境、关注关系以及用户在本产品中的显式校准。浏览、停留、重复阅读、点赞等信号只有在开放平台实际提供并获得用户授权时才可启用，不得从现有数据反向猜测。

### 11.3 敏感领域治理

- 政治、宗教、医疗健康、性取向等高风险领域默认不进行个人立场推断；
- 若产品允许在某敏感领域进行个人分析，必须由用户按领域主动开启，而不是先推断再让用户关闭；
- 用户拒绝某项推断后，系统只保存不可反推具体立场的模型反馈特征，且有独立保留期；
- 敏感领域不生成可公开分享的个人光谱。

### 11.4 观点晶体

用户校准后生成 `ViewpointCrystal`，包含：

- 当前判断；
- 形成和确认时间；
- 依赖的证据与原文链接；
- 成立条件与失效边界；
- 尚未解决的问题；
- 可能使判断改变的新证据类型；
- 与上一版晶体的变化；
- 系统推断部分与用户确认部分的明确区分。

## 12. 长期认知服务

### 12.1 认知快照

系统对个人宇宙进行版本化，每次同步不重做无关联的新星图，而是计算与上一快照的变化：

- 哪些恒星变亮、变暗或熄灭；
- 哪些问题行星新出现；
- 哪条文章航迹连接了原本分离的概念；
- 哪枚观点晶体受到新证据冲击；
- 用户是否开始创作过去只收藏的主题。

快照差异必须区分三种来源：

- **用户数据变化**：用户收藏、创作、关注或显式校准发生变化；
- **公共知识变化**：问题出现新公共内容、新快照或来源失效；
- **系统分析变化**：模型、概念归并、布局或分析规则版本更新。

不同 `analysisVersion` 的结果默认不直接生成「你的兴趣变了」或观点冲突事件。系统必须优先用经隐私审查、可重算的最小派生特征在新旧版本中做同口径比较；无法重算时，只能标记为「系统重新建模」，不表述为用户认知演化。

### 12.2 认知事件

| 事件 | 触发含义 |
|---|---|
| 新证据抵达 | 观测问题出现高质量新答案、新数据或新长文 |
| 认知地震 | 主流立场、证据基础或讨论框架发生显著变化 |
| 观点冲突 | 新内容与用户已确认判断或历史晶体存在结构性矛盾 |
| 盲区显现 | 现有可观测个人证据长期只覆盖某一立场，缺乏强反例或不同适用情境 |
| 表达时刻 | 用户已积累足够阅读、判断和证据，可以形成有价值的回答或文章 |

每种事件在技术规格中必须定义最低独立来源数、变化显著性或置信阈值、去重窗口、冷却期、失效条件和延迟容忍。用户可对每条事件标记「有用」「误报」或「不想再看此类」，反馈进入后续规则和模型评估。

「表达时刻」仅在用户主动请求或显式开启该类提示时生成，产品不默认评判用户是否「有资格」表达。

### 12.3 观测清单

只对用户主动选择的行星做持续观测。每颗行星可单独设置：

- 仅在发生认知地震时提醒；
- 出现强反例时提醒；
- 观点晶体可能失效时提醒；
- 按用户选择的周期生成演化摘要；
- 暂停观测。

事件通知必须说明「什么变了」「为什么对你有关」和「依据在哪里」，不只报告新增内容数量。

### 12.4 无持久 token 的观测闭环

持续观测分为两条互不混淆的管线：

- **公共行星管线**：无需持有用户 OAuth token，根据观测清单定期查看公共问题的新内容和新快照，在应用内生成认知事件；
- **个人足迹管线**：仅在用户主动重新授权/同步后，计算收藏、创作、关注和个人宇宙的增量变化。

所有周期摘要必须分别显示「公共问题观测截至时间」与「个人足迹同步截至时间」。重新授权失败、公共接口限流或事件延迟时，只标记对应管线过期，不影响另一条管线和已有档案。

### 12.5 表达准备包

当用户主动请求表达帮助时，系统可生成：

- 问题的历史脉络；
- 主要立场及盲区；
- 用户已确认的判断；
- 可以回到原文的证据；
- 尚需补充的证据；
- 当前讨论中值得回答的空白角度。

系统不自动替用户发布，最终表达必须由用户确认并回到知乎完成。

## 14. 核心用户故事与验收

### US-00 安全找回长期认知账户

**作为**返回产品的用户，**我希望**重新登录后只找回属于自己的观点晶体和认知档案，**以便**安全地持续使用。

验收：

- 仅使用平台返回的稳定、不可变用户标识绑定认知账户，不使用昵称、头像或可变 URL 当身份键；
- OAuth token 可短存，但应用自身身份 session、设备登出和重新认证状态可管理；
- 平台不提供稳定用户标识时，长期账户不启用，产品降级为会话结果和用户主动导出；
- 删除账户、从全部设备登出和重新登录均有端到端验证。

### US-01 从个人足迹建立宇宙

**作为**知乎用户，**我希望**在知情的情况下授权个人足迹，**以便**看到与自己真实相关的认知宇宙。

验收：

- 授权前说明使用的数据类型、用途和保留方式；
- 不同数据源在星图中可追溯；
- 数据不足时明确降级，不伪装成完整个人宇宙；
- 用户可撤销授权、删除个人认知数据。

### US-02 从概念进入真实问题

**作为**探索者，**我希望**点击概念恒星后看到真实知乎问题，**以便**从模糊兴趣进入可被回答和验证的议题。

验收：

- 行星主体对应真实问题 ID 和原页链接；
- 相关问题位于行星环，不混入主问题纪年；
- 个人已有可观测关联与公共推荐可被区分；
- 用户可以直接回到知乎问题原页。

### US-03 查看问题的历史地层

**作为**学习者，**我希望**看到各时期的主要观点和转折，**以便**理解当前认识是如何形成的。

验收：

- 每个地层显示内容数量、时间范围和来源覆盖；
- 转折点包含可点回的代表性证据；
- 数据不足时不生成虚假地层；
- 年份、时间范围和事件日期不得由模型自由生成；
- 每个地层显示当前是「回溯观测」还是「快照纪年」；
- 回溯观测不展示当年主流份额，并常驻幸存者偏差警示；
- `published_at`、`updated_at`、`observed_at` 可分别查看且不被互相替代；
- 无历史正文版本时，回溯界面明确标记为「按内容容器首发时间排列的当前版本」，不声称当前观点在首发时即已存在。

### US-04 对任意地层进行棱镜分光

**作为**深度阅读者，**我希望**比较各立场的证据、前提和边界，**以便**理解分歧而不是只选边。

验收：

- 可在当前地表和任意有足够数据的历史地层启动；
- 每个高层概括至少有一条可追溯观点单元支持；
- 不存在明显阵营时展示连续光谱；
- 事实陈述、经验判断、价值判断和 AI 推断明确区分；
- 统计份额以独立内容/作者为口径，不按 PublicClaim 数量投票；
- 文章只在旁轨提供论证，不计入答案或社区份额。

### US-05 形成个人观点晶体

**作为**用户，**我希望**看到系统对我的推断并逐项校准，**以便**形成真正属于我的判断，而不是接受 AI 标签。

验收：

- 每项推断展示依据和置信度；
- 用户可设置「尚未形成判断」；
- 用户可删除某条内容对推断的影响；
- 晶体仅在用户确认后持久化；
- 后续修改新建版本，不覆盖历史判断。

### US-06 持续观测与更新

**作为**长期用户，**我希望**只在重要变化发生时被提醒，**以便**维护判断而不被新内容数量淹没。

验收：

- 只有用户主动加入观测的行星被持续追踪；
- 每条通知说明变化、个人相关性与来源；
- 用户可暂停单颗行星或全部观测；
- 新证据只触发重新审视，不自动改写用户晶体；
- 事件有去重、冷却、失效和用户误报反馈机制；
- 周期摘要分别显示公共数据和个人足迹的最近更新时间。

### US-07 从认知回到表达

**作为**准备创作的用户，**我希望**整理历史脉络、观点结构和我的判断，**以便**在知乎写出更有价值的回答或文章。

验收：

- 表达准备包中的证据均可回到原文；
- 明确区分用户已确认判断和 AI 建议；
- 不绕过用户自动发布；
- 新创作同步后成为新的答案卫星或文章探测器。

## 15. 统一领域模型

```text
PublicKnowledgeGraph
├── Concept[]                         # 全局公共概念，无个人亮度/位置
├── Question[]                       # 以知乎 question_id 全局唯一
├── ConceptQuestionEdge[]            # 公共概念 ↔ 问题，多对多
├── RelatedQuestionEdge[]            # 问题 ↔ 问题，可纠正
├── ContentArtifact[]                # 答案/文章全局唯一
├── ContentBinding[]                 # 内容 ↔ 问题
├── PublicClaim[]
├── ExternalEvidenceArtifact[]       # 全网来源，只进入证据旁轨
├── ExternalClaim[]
├── EvidenceQuestionBinding[]
├── Chronicle[]
│   ├── TimeStratum[]
│   └── TurningPoint[]
└── Prism[]
    ├── StanceSpectrum[]
    └── AnalysisFacet[]

UserCognitiveGraph
├── User
├── ConsentRecord[]
├── UniverseSnapshot[]
├── UserCluster[]                    # 个人星群与布局
├── PrivateConcept[]                 # 租户隔离，不自动进入公共图谱
├── UserConceptStar[]                # 引用公共 Concept 或 PrivateConcept
├── UserStarQuestionBinding[]        # 个人恒星 ↔ 全局问题，保存个人优先级
├── UserContentBinding[]              # 收藏/创作，严格租户隔离
├── UserCreatorFollowBinding[]        # 关注创作者，弱兴趣信号
├── UserTopicFollowBinding[]          # 关注话题，弱兴趣信号
├── UserInferenceEvidence[]           # 个人推断证据，不进入公共缓存
├── ViewpointCrystal[]
├── WatchRule[]
└── CognitiveEvent[]
```

### 15.1 共同原子：PublicClaim

三个子系统共享的公共语义原子是可追溯的 `PublicClaim`：

- 精神宇宙回答它与用户及哪些概念相关；
- 答案纪年回答它在什么时间出现、如何扩散或被修正；
- 观点棱镜回答它属于哪个判断结构、依赖什么前提和边界。

一个 `PublicClaim` 必须关联到内容 ID、原文 URL、作者、时间和可定位的来源片段，不得仅保存 AI 摘要。用户是否收藏该内容、如何校准、拒绝过什么推断，只存在于 `UserContentBinding` 和 `UserInferenceEvidence`，任何公共 Claim、缓存、纪年或棱镜结果不得携带用户 ID。

公共 `Concept` 只表示已被公共知乎内容独立证明存在的语义概念。恒星是 `UserConceptStar`：它可引用公共 `Concept` 或租户隔离的 `PrivateConcept`，其亮度、位置、持续性、爆发度、熄灭状态和星群归属全部属于单个用户，不在用户之间共享。

收藏夹标题、用户自定义分类、只在私人足迹中出现的稀有概念与敏感概念默认建模为 `PrivateConcept`，不创建公共 `Concept/ConceptQuestionEdge`。只有概念已由公共内容独立证明存在，或经过明确的去标识化门槛审查，才能晋升为公共 `Concept`。单个用户的私人绑定不得反向生成公共概念或关联边。

`UserCreatorFollowBinding` 和 `UserTopicFollowBinding` 只表示弱兴趣信号，必须通过可解释的公共关系间接关联问题，不得伪装成用户读过、收藏或认同某篇内容。每条派生问题关联保存 `direct/inferred`、原始依据、分析版本和置信度，界面始终表述为「你关注的创作者/话题与此问题相关」，不表述为用户关注了该具体问题。

### 15.2 外部证据旁轨

全网搜索获得的网页不进入知乎 `ContentArtifact` 或 `PublicClaim`，而由 `ExternalEvidenceArtifact` 和 `ExternalClaim` 独立承载，至少保存站点、URL、作者/机构、发布时间、抓取时间、来源可信度、定位信息和失效状态。

外部证据只能通过 `EvidenceQuestionBinding` 进入证据旁轨、反例或事实核验层，绝不参与知乎答案数、知乎作者数、光谱份额或社区主流计算。

### 15.3 分级来源保全

| 来源类型 | 默认保存 | 原文删除/变更后 |
|---|---|---|
| 公共内容 | 内容 ID、抓取/分析版本、最小必要引文、定位 selector、引文哈希 | 停止展示失效原句，保留不可逆哈希和「来源失效」状态 |
| 私人 OAuth 内容 | 来源 ID、派生特征和用户绑定 | 不保留原句；需保存引文时单独获得同意，并遵守独立保留期 |
| 用户显式写入晶体的内容 | 用户确认的文本与版本 | 作为用户自身认知记录保留，但关联的失效外部引文不继续展示 |

最小必要引文长度、版权口径、保留期、selector 类型和重定位失败状态必须在技术与合规规格中明确。

### 15.4 关键关联

- `ContentBinding`：将内容与问题绑定，并标记为核心论点、证据、反例或背景；
- `CrystalEvidence`：将用户晶体与确认过的 `PublicClaim` 或私人来源索引绑定；
- `StratumMembership`：将 `PublicClaim` 绑定到历史地层；
- `SpectrumMembership`：将 `PublicClaim` 绑定到某个光谱与分析轴。

## 16. 数据与 AI 流水线

1. **授权与采集**：短期读取 OAuth 范围内的用户足迹；
2. **内容规范化**：统一问题、答案、文章、作者、时间与 URL；
3. **概念提取与归并**：沿用现有 mindverse 语义引擎构建个人概念图；来自收藏夹标题、用户标签或仅有私人证据支持的概念默认进入 `PrivateConcept`，不写入公共概念图；
4. **问题解析**：优先从内容中恢复真实问题 ID，再用知乎搜索扩展高价值问题；
5. **个人关联建模**：建立用户、概念、问题、内容、作者与时间的关系；
6. **公共内容扩充**：通过已验证的问题级数据能力获取可追溯答案样本和相关文章；仅有搜索样本时必须保留「代表性样本观测」口径；
7. **观点单元提取**：将可用公共内容拆解为有来源的 `PublicClaim`，区分事实、经验、价值和预测；
8. **外部证据补充**：将全网来源独立建模为 `ExternalEvidenceArtifact/ExternalClaim`，只进入证据旁轨；
9. **时间建模**：分别记录首发、编辑和观测时间；回溯样本只用于内容容器年代观测，连续快照/历史正文才用于观点时序、份额变化和转折候选；
10. **棱镜分析**：聚合光谱，提取证据、前提、价值、边界与风险；
11. **个人光谱推断**：根据 `UserInferenceEvidence` 进行逐轴推断，保留反例和置信度；
12. **用户校准**：将推断与用户确认内容分离；
13. **版本化与观测**：保存认知快照、`schemaVersion/analysisVersion` 和最小可重算特征，分别计算用户数据、公共知识与系统重建变化。

## 17. 数据与隐私边界

### 17.1 总原则

**认知结果长期保存，OAuth 原始数据短期使用。**

### 17.2 长期保存

- 经用户同意建立、以平台稳定不可变用户标识绑定的认知账户；
- 宇宙结构与版本快照；
- 问题行星和个人轨道的派生关系；
- 用户确认的观点晶体；
- 观测清单和用户设置；
- 内容 ID、URL、时间、提取版本等重新验证索引；
- 经用户同意且通过隐私审查的最小可重算派生特征（如去原文化的内容类型、时间、概念关联与受控向量），仅用于分析版本重算与差异归因；
- 用户对系统推断的修改和模型反馈；敏感领域的拒绝只保存不可反推立场的规则特征并单独设定保留期。

### 17.3 默认不长期保存

- OAuth access token；
- 完整 OAuth 原始响应；
- 不必要的回答和文章全文副本；
- 未经用户确认的敏感推断；
- 模型处理中间临时上下文。

`PrivateConcept`、敏感领域和可反推敏感主题的向量/派生特征默认不持久化，仅本次会话可见。用户可以在预览具体字段后，选择对指定 `PrivateConcept` 加密持久化；该选择需单独同意、租户隔离、独立保留期，并纳入导出、模型排除和硬删除范围。

未持久化的私人恒星在快照中只保存「因隐私策略未保存的私人星体数量」和策略版本，不保存可反推概念的名称或特征。下次会话无法还原该恒星时，界面必须说明「上次未保存的私人星体需重新生成」，不将其消失解释为兴趣熄灭或用户认知变化。

### 17.4 用户控制权

用户必须能够：

- 查看任何个人推断的来源；
- 删除某条内容对个人模型的影响；
- 关闭特定领域的分析；
- 删除单颗问题行星；
- 导出观点晶体和认知历史；
- 清空全部个人数据；
- 暂停或关闭长期观测。
- 查看、导出或删除为分析版本重算保存的派生特征。

### 17.5 删除、排除与隐藏的级联语义

| 用户动作 | 作用范围 | 历史处理 |
|---|---|---|
| 界面隐藏 | 仅改变当前用户视图 | 不改变分析与历史 |
| 模型排除 | 指定私人内容不再参与个人推断 | 重算受影响的当前结果；历史晶体标记依据已被用户排除，不再展示该私人证据 |
| 删除个人行星绑定 | 删除用户与该公共问题的轨道、晶体和观测规则 | 不删除公共 `Question`、`PublicClaim` 或其他用户数据 |
| 硬删除个人数据 | 主库、索引、快照、缓存、分享副本中的全部个人数据 | 历史晶体中的私人证据和可反推拒绝信息同步删除或不可逆匿名化 |
| 公共来源失效 | 公共来源状态 | 全局标记失效，停止展示原句，但不因单个用户删除公共问题实体 |

「历史版本不覆盖」不能用于对抗用户硬删除权。

### 17.6 分享边界

现有快照分享仅作为可复用的工程基础，不原样沿用其数据边界。融合产品必须新建显式 `ShareView`：

- 默认不分享整个人宇宙；
- 用户逐项选择要分享的星体、公共纪年、棱镜或已确认晶体；
- 默认移除收藏/创作区分、个人时间轨迹、未确认推断、私人内容绑定与用户拒绝记录；
- 分享前显示准确预览和可见字段；
- 删除账户或对应个人对象时，级联删除所有相关分享副本。

## 18. 现有 mindverse 接入设计

### 18.1 保留能力

现有代码作为融合产品底座，保留：

- Go 服务与 OAuth 授权链路；
- 内存中的 token 管理原则；
- 概念提取、二部图、社区发现与空间布局；
- 星群、恒星、虫洞、孤星、熄灭恒星和星云概念；
- React 状态管理、WebGL 星图和逐级拉远导航；
- 真实证据回链以及分享快照的工程能力；分享数据必须按 §17.6 重新定义，不原样继承当前个人星群和足迹字段。

### 18.2 语义升级

现有对象为：

```text
Cluster → Star → Evidence（当前被渲染为行星）
```

升级为：

```text
UserCluster → UserConceptStar → QuestionPlanet
                                 ├── AnswerSatellite
                                 └── ArticleProbe
```

不推翻现有外层宇宙，而是在 `Star` 和 `Evidence` 之间增加问题层，并将现有内容行星分化为答案卫星和文章探测器。

这是一次带数据迁移的契约升级，不是只增加一个前端展示层。所有核心实体必须拥有稳定 ID：

- 问题、答案和文章保留知乎原始 `question_id/content_id`；
- 公共 `Concept` 和个人 `UserConceptStar` 分开标识；个人恒星不得仅以可变概念名称作为引用键，需要快照内稳定 ID 和跨版本映射；
- `UniverseSnapshot`、分享快照和公共分析均包含 `schemaVersion` 与 `analysisVersion`；
- 废弃只能表达两态的历史 `Own bool`。`UserContentRelation` 只保存 `created`、`collected` 等真实用户关系；`public_discovered` 属于独立 `DiscoverySource`/前端展示状态，不创建 `UserContentBinding`；
- 旧快照通过只读适配器展示，不在缺少问题 ID 时伪造新行星；无法适配的快照明确标记为旧版本，不参与新分析。

### 18.3 前端主要接入面

| 现有位置 | 融合方向 |
|---|---|
| `frontend/src/types.ts` | 扩展问题、内容类型、纪年、棱镜、晶体和观测事件契约 |

| `frontend/src/starmap/gl/bodies.ts` | 区分问题行星、答案卫星与文章探测器的程序化几何 |

## 20. 状态与降级

| 情况 | 产品表达 | 不允许的行为 |
|---|---|---|
| OAuth 未配置/失效 | 保留已有认知结果，引导重新授权；可进入公共模式 | 伪装已同步 |
| 无稳定授权用户 ID | 降级为会话结果与用户主动导出 | 用昵称、头像或 URL 找回长期账户 |
| 个人数据不足 | 展示数据范围，允许选择种子方向 | 将游客结果宣称为个人历史 |
| 问题级数据只是搜索样本 | 标记「代表性样本观测」并展示覆盖量 | 声称覆盖全部回答或社区共识 |
| 问题过新/答案过少 | 只展示当前地表与可用原文 | 虚构历史地层 |
| 仅有当前幸存样本 | 按首发时间展示回溯观测，常驻幸存者偏差提示 | 声称当年份额、排名、主流或少数派迁移 |
| 无明显阵营 | 展示连续光谱或多轴差异 | 强行凑出固定数量的派别 |
| 个人推断低置信 | 显示「尚不了解你的判断」及缺失依据 | 用弱行为宣布立场 |
| 原文被删除 | 停止展示原句，仅保留来源 ID、不可逆哈希、分析版本和失效状态 | 隐藏来源失效或继续展示失效原句 |
| 外部证据与知乎观点冲突 | 分轨展示 | 混合后声称为知乎社区共识 |
| 模型无法判断 | 明确弃权或请用户补充 | 为了视觉完整填充结果 |
| 敏感类目被过滤 | 说明未参与分析的范围和数量 | 暗示分析覆盖全部足迹 |
| 后台分析未完成 | 分段展示真实进度，先提供可用外层结果 | 伪造精确百分比或阻断已可用功能 |

## 21. 可解释性与诚实性规则

1. 所有关键评估均区分「原始信号」「算法聚合」「AI 解释」「用户确认」。
2. 每个地层、转折、光谱和个人推断均有证据覆盖指标。
3. 任何高层概括都能下钻到适用的来源类型：公共分析进入 `PublicClaim/ExternalClaim`，个人分析进入租户隔离的 `UserInferenceEvidence` 或用户确认记录；私人来源不因可解释性要求被提升到公共图谱。
4. 时间、作者、互动数据与 URL 不由模型生成。
5. 模型提取的隐藏前提、适用边界和风险必须标记为分析性推断。
6. 收藏、关注和点赞不自动等价为用户认同。
7. 用户对推断的拒绝必须成为后续模型的负证据，避免重复误判。

## 22. 产品评价指标

### 22.1 核心价值指标

- 完成 OAuth 后进入至少一颗真实问题行星的比例；
- 用户从 AI 概括点回原文进行验证的比例；
- 完成至少一次观点校准的比例；
- 产生后续版本的观点晶体数量与变化原因；
- 认知事件发生后重新进入行星的比例；
- 从表达准备返回知乎创作的比例。

### 22.2 分析质量指标

- `PublicClaim` 原文可追溯率；
- 地层与光谱的来源覆盖率；
- 问题归并的用户纠正率；
- 个人位置推断的用户修改/拒绝率；
- 系统在证据不足时的弃权准确性；
- 转折候选经人工复核后的成立率；
- 被删除或不可访问来源的更新及时性。

### 22.3 不作为核心指标

- 生成了多少颗星；
- 单次动画播放时长；
- 静态分享卡的曝光量；
- 被 AI 归入某个阵营的用户数；
- 没有回到原文的摘要阅读量。

## 23. 质量与测试要求

### 23.1 数据契约

- Go JSON tag 与 TypeScript 类型持续逐字对齐；
- 问题、答案、文章和观点单元不可混淆类型；
- 问题/内容原始 ID、快照 ID、模式版本和分析版本全链路不丢失；
- `Concept/PrivateConcept`、`UserContentRelation` 和内容/创作者/话题关注绑定类型不得混淆；
- 单个用户的收藏夹名、私人标签和稀有概念不能在公共概念图谱或公共缓存中被查询到；
- 同一问题经多个恒星入口访问时始终引用同一份纪年、棱镜和观测资源；
- 同一文章经过多个问题时仅保存一份实体；
- 快照必须可重放、可比较并带分析版本。

### 23.2 AI 评估集

至少建立以下可重复评估的标注集：

- 问题识别和相关问题环；
- 答案/文章内的观点单元提取；
- 事实、经验、价值、预测的分类；
- 地层切片和转折点候选；
- 立场聚类与连续光谱判断；
- 隐藏前提、适用边界和反例的来源支持；
- 个人位置推断、置信度与应当弃权的样本；
- 认知事件是否真正具有重新审视价值。

### 23.3 产品与交互测试

- 宇宙→恒星→问题行星→观察模式→原文全链路；
- 鼠标、键盘、触控与减少动效偏好；
- 中途取消、重试、授权失效、搜索限流与部分数据返回；
- 低性能设备下保留证据链和主流程；
- 长标题、中英混排、高密度地层与光谱在小屏不截断核心信息；
- 删除个人数据、撤销观测和导出档案端到端生效。

### 23.4 安全与隐私验证

- OAuth state、cookie、回调、token 交换与过期处理；
- 稳定授权用户 ID 绑定、重新认证、设备登出与账户串线防护；
- 查询外发安全：私人概念、收藏夹名、用户自述和晶体文本不会被自动发送到站内/全网搜索；
- token、App Key、Access Secret 和 authorization code 不进入日志、快照和前端响应；
- `ShareView` 预览与实际公开字段逐项一致，不包含私密足迹、收藏/创作区分、未确认推断和不必要原始内容；
- 数据删除覆盖主库、索引、快照、缓存和分享副本；
- 推断性敏感内容默认不入库，并提供用户主动排除能力。
