# 知见宇宙 · 寂静深空材质与文章探测器设计

版本：v1.0  
日期：2026-08-31  
状态：已完成产品确认，待规格审查

## 1. 目标

本轮只处理三个视觉承重层：宇宙环境、问题星球、文章探测器。目标不是继续叠加特效，而是把现有星图从“彩色星云中的知识节点”收束为“可被操作和核验的深空知识天文台”。

本轮同时修复正式构建中的 Three.js 运行时黑屏。视觉增强必须建立在可验证的生产构建之上。

不在本轮范围：新手村、分享弹窗、答案纪年二维界面、观点棱镜业务逻辑、OAuth 与后端数据模型。

## 2. 已确认的视觉方向

采用 **A · 寂静深空**：

- 深黑负空间占画面主体，星云只作为低亮度环境层。
- 电影感来自真实明暗、尺度、材质、景深和镜头节奏，不来自常驻霓虹、色差与过量 Bloom。
- 三维空间负责尺度与方位；二维 UI 继续承担精确阅读、证据和操作。
- 色彩仍服从既有语义：低饱和星蓝是公共知识环境，琥珀只表示用户创作或文章探测器等已定义关系。
- 不使用地球、木星、月球等照片贴图，避免给问题附加虚构的天体含义。

## 3. 场景层级

### 3.1 远景宇宙

- 约 70% 画面保留深黑负空间。
- 三层星云壳继续存在，但总增益显著降低；核心白雾缩小并压暗。
- 常态关闭可见 RGB 色差，降低 Bloom 半径和强度。
- 全景默认只显示 5–7 个优先星群标签，其余标签在靠近或聚焦后渐显。
- 非当前星系的轨道、标签和辅助线主动退让，避免与当前操作目标竞争。

### 3.2 中景恒星系

- 聚焦恒星后才展开完整问题行星、主要轨道和文章探测器。
- 背景星云与非当前星群进一步退暗。
- 行星保持由所属恒星照明，确保昼夜面方向在相机移动时稳定。
- 探测器以可识别剪影进入问题轨道，不在远景显示全部结构细节。

### 3.3 近景对象

- 聚焦问题星球时，启用高频法线细节、薄大气、云层或地层结构。
- 聚焦文章探测器时，进入独立检查状态，用户获得相机控制权。
- 近景对象之外的场景继续存在，但降低亮度和信息密度，维持空间连续性。

## 4. 问题星球材质系统

### 4.1 原则

每颗问题星球使用统一的电影级程序化材质管线。外观由公开且可解释的问题指标生成，并使用稳定 seed 保证同一问题跨会话外观一致。

材质差异不能替代事实判断。没有数据时使用中性默认值，不根据问题标题主观推测地貌。

### 4.2 数据映射

| 数据 | 视觉参数 | 无数据时 |
|---|---|---|
| 回答数量 | 大尺度山脊、盆地与纹理密度 | 低密度中性表面 |
| 可观测时间跨度 | 地层数量、层带尺度 | 不显示强地层 |
| 最近公开活跃度 | 大气厚度、云层强度与反照率 | 低大气、低反照率 |
| 可观测观点分歧 | 板块断裂与明暗边界复杂度 | 不推断分歧，保持连续地貌 |
| 用户创作关系 | 夜面少量琥珀灯火 | 无自发暖光 |
| 仅收藏或浏览关系 | 只反射所属恒星光 | 同左 |
| 当前选中 | 临时扫描经纬线 | 不改变基础材质颜色 |

若现有 Universe 数据没有“时间跨度”或“观点分歧”字段，本轮只能预留材质输入并使用中性值，不从回答数量反推这些指标。

### 4.3 材质家族

第一轮提供四个共享光照模型的材质家族：

1. **玄武岩**：低反射、细裂纹、较强粗糙度。
2. **层积岩**：连续层带与可读沉积结构，承担答案纪年隐喻。
3. **云层**：薄大气与极慢云流，表达近期公开活动。
4. **档案金属**：低亮度拉丝和刻度结构，强调知识档案感。

家族分配使用问题 ID 稳定 seed；数据只调节材质参数强度。家族本身不代表问题类别、价值或立场。

### 4.4 LOD 与性能

- 远景：点精灵或简化球体，不启用高频材质。
- 中景：基础明暗、低频地貌和大气轮缘。
- 近景：增加程序化法线、粗糙度、地层或云层。
- 不引入 2K/4K 照片贴图；若后续需要采样纹理，限制为 256–512px KTX2/Basis，并按近景状态懒加载。
- reduced motion 关闭云层流动和扫描扫过动画，但保留静态材质语义。

## 5. 文章探测器

### 5.1 视觉身份

文章探测器必须与恒星、问题星球和答案卫星明显不同：

- 深色陶瓷六棱舱体。
- 两片折页式金属侧翼，同时具备仪器与书页的联想。
- 琥珀数据灯带，表示文章实体及用户创作关系。
- 推进器、天线、扫描镜头、舱体接缝和蚀刻刻度只在中近景出现。
- 不复刻现实 NASA 卫星，也不做攻击性飞船造型。

模型由项目内程序化 Three.js 几何生成，不依赖外部模型版权或网络资源。

### 5.2 三级 LOD

| 层级 | 显示内容 | 目标 |
|---|---|---|
| 远景 | 舱体、侧翼、琥珀信标的低多边形剪影 | 大量实例稳定显示 |
| 中景 | 折页结构、推进器、天线、舱体刻线、姿态调整 | 清楚识别为文章探测器 |
| 近景 | 完整部件、PBR 粗糙度、金属接缝、微型蚀刻、灯带内部、扫描镜头 | 支持主动检查 |

LOD 切换使用交叉淡化或等价的无跳变过渡。低画质保留近景模型的主要轮廓和主动操作，但降低材质采样与小部件数量。

### 5.3 近景主动操作

进入探测器近景后，自动镜头暂停，用户拥有控制权：

- 鼠标拖拽或单指拖动：360° 旋转。
- 滚轮或双指手势：缩放。
- 右键拖拽或双指移动：平移构图。
- 双击部件：聚焦部件并显示功能标注。
- 点击“归位”：恢复标准电影镜头。
- 点击“开始扫描”：展开侧翼、投射扫描扇面，并打开既有文章证据路径。
- 点击问题星球或按 Esc：退出探测器检查并返回问题星球。
- 键盘方向键旋转，`+`/`-` 缩放，Tab 切换可聚焦部件。

相机必须限制最近距离、最远距离和平移半径，避免穿模或丢失对象。用户停止操作后只恢复轻微悬浮，不自动夺回视角。

reduced motion 关闭自动悬浮、侧翼展开过渡和自动运镜，但保留由用户直接驱动的旋转、缩放和平移。

### 5.4 扫描动作

第一轮实现：轨道停泊、轻微姿态、侧翼展开、窄幅扫描光束和扫描入口。

扫描由用户主动触发。扫描光束只承担“文章正在读取这颗问题星球”的状态反馈，不伪造引用关系；实际文章—问题—答案证据继续来自现有数据与面板。

## 6. 技术边界

新增模块按职责拆分：

- `gl/cinematic.ts`：宇宙环境与后期参数常量。
- `gl/planetMaterials.ts`：材质输入归一化、稳定 seed 和 Shader 构造。
- `gl/probe.ts`：探测器几何、材质与三级 LOD。
- `probeInspection.ts`：近景检查状态、相机约束与输入映射。
- `Renderer.ts`：只负责组合这些系统、切换聚焦对象与每帧更新，不继续堆积具体几何实现。

材质输入先通过纯函数从现有 Universe 数据归一化，Shader 不直接理解业务字段。这样可以独立单测数据映射，并在未来接入答案纪年和观点棱镜指标时保持兼容。

## 7. 正式构建黑屏修复

当前正式构建中 Renderer 动态导入失败，错误指向 Three.js 被拆分后的继承依赖。设计要求：

1. 取消对 Three.js 源码模块的危险 `maxSize` 强拆，或将 Three.js 保持为经浏览器验证的完整 vendor chunk。
2. 生产构建完成后，真实浏览器必须能动态导入 Renderer。
3. Canvas backing store 必须匹配可见尺寸，不能停留在默认 `300 × 150`。
4. 首帧必须产生非空渲染结果。
5. Renderer 初始化失败时显示可操作的降级界面：错误说明、重试 3D、文本星群列表；不能只显示黑屏。

视觉实现不得绕过这项修复，也不得用开发服务器成功代替生产构建验证。

## 8. 状态与数据流

1. Universe 数据进入纯函数，生成星球材质参数和文章探测器实例数据。
2. Renderer 根据相机距离选择星球与探测器 LOD。
3. 用户选择文章后，Renderer 进入 `probe-approach`，将探测器带入目标问题轨道。
4. 抵达后进入 `probe-inspection`，自动相机停止并启用检查控制器。
5. 用户触发扫描后进入 `probe-scanning`，播放可降级动画并打开现有证据入口。
6. 退出后返回 `planet-focus`，恢复星球操作和原有导航语义。

任一视觉模块初始化失败时，状态机必须回到可操作的上一层，而不是停留在中间状态。

## 9. 测试策略

### 9.1 单元测试

- 稳定 seed：相同问题 ID 结果一致，不同 ID 能产生稳定差异。
- 材质映射：边界值、缺失字段、中性降级和语义不串用。
- LOD：相机距离临界点及滞回，避免来回闪烁。
- 检查控制器：旋转、缩放、平移约束与归位。
- reduced motion：关闭自动动画但保留主动输入。

### 9.2 集成与浏览器测试

- 生产构建动态导入 Renderer 成功。
- Canvas 尺寸正确，首帧非空。
- 从全景进入问题星球，再进入探测器检查，可旋转、缩放、归位和退出。
- 扫描完成后打开正确文章证据，不制造不存在的关联。
- WebGL 或 Shader 初始化失败时出现降级界面。

### 9.3 视觉与性能验收

- 远景黑色负空间明显多于星云，标签不超过默认上限。
- 常态无明显 RGB 色散；Bloom 不吞没星球轮廓。
- 近景星球可辨认昼夜面、材质家族和数据驱动差异。
- 探测器在远、中、近景均保持同一身份，LOD 无明显跳变。
- 1080p 中等画质保持流畅；低画质和 reduced motion 路径可用。

## 10. 实施顺序

1. 先写生产渲染失败的浏览器回归测试，并修复 Three.js 打包。
2. 收束宇宙环境、星云、Bloom 和色差。
3. 抽出星球材质输入纯函数，先测试再扩展 Shader。
4. 实现探测器几何与三级 LOD。
5. 实现近景检查控制器和主动扫描。
6. 完成生产构建、浏览器、性能、reduced motion 和降级验证。

## 11. 验收定义

本轮完成时，用户可以从稳定运行的正式构建进入一片以深黑负空间为主的宇宙，聚焦一颗具有可解释材质的问题星球，看见文章探测器从远景剪影逐级变为可检查的近景模型，并主动旋转、缩放、平移、聚焦部件及触发扫描；任何视觉失败都不会阻断问题、文章和证据入口。
