# Mindverse · Babylon 恒星视觉与交互设计

版本：v1.0  
日期：2026-09-02  
状态：用户已确认设计方向，规格复审通过

## 1. 背景与目标

Babylon 垂直样片目前把每颗恒星实现为一个最小直径 `0.6` 世界单位的低面数自发光球。宇宙全景中，这些球体投影后只剩点阵；Babylon 的几何拾取又严格依赖球体真实轮廓，导致恒星难以点击。命中后相机直接修改目标和半径，没有悬停、聚焦、飞近和层级展开反馈。

本阶段将恒星视觉、拾取与镜头过渡统一为“恒星交互单元”，恢复并提升以下完整体验：

1. 宇宙全景中的恒星必须首先被识别为发光天体，而非均质数据点；
2. 每颗可见恒星都具有稳定、易用且不与视觉尺寸强耦合的命中区域；
3. 悬停、按下、聚焦和返回均有明确反馈；
4. 点击恒星后，镜头平滑飞入恒星系，并在过程中逐级揭示恒星表面、问题行星和轨道；
5. 保持“问题行星 → 答案地层”的既有业务状态和数据语义不变；
6. Reduced Motion、键盘入口、触控和低画质模式仍可完成相同语义操作。

本规格不迁移探测器近景、不重做答案地层，也不增加新的知乎数据推断。

## 2. 体验状态

恒星交互层消费现有主状态，新增的 hover 与相机动画仅是表现状态，不成为 React 业务状态。

```text
PANORAMA
  --hover--> STAR_HOVER（瞬时表现态）
  --click/keyboard--> STAR_APPROACH（镜头表现态）
  --arrive--> STAR_FOCUS
  --select planet--> PLANET_FOCUS
  --open workspace--> PLANET_OBSERVATORY
PLANET_FOCUS / PLANET_OBSERVATORY
  --zoom out / blank click / close--> STAR_FOCUS
STAR_FOCUS
  --zoom out / blank click / close--> PANORAMA
```

- `PANORAMA`：显示所有恒星的远景星核和光晕；仅显示已确定的宏观星群轨道。
- `STAR_HOVER`：目标恒星光晕与轮廓增强，Canvas 光标切换为 pointer；不得让恒星位置或命中目标跳动。
- `STAR_APPROACH`：相机目标、距离与背景强调连续插值；目标恒星从远景表示平滑切换为近景表面。
- `STAR_FOCUS`：目标恒星成为视觉主体，所属问题行星及其轨道展开，非当前恒星降低存在感但仍保留空间方向提示。
- `PLANET_FOCUS`：选中轨道强调，其他问题轨道降低；恒星保持为可见光源和空间参照。
- 答案地层状态：全部宇宙恒星表现与拾取禁用，保持现有单 Canvas 穿越逻辑。

## 3. 恒星交互单元

每颗恒星对应一个轻量 `StarVisualHandle`，由批量资源驱动，不为每颗恒星复制 Mesh、完整纹理、材质或后处理实例。

```ts
interface StarVisualHandle {
  datum: StarDatum
  instanceIndex: number
  batch: 'panorama' | 'focused'
}

interface SharedStarVisualResources {
  panoramaCoreBatch: StarInstanceBatch
  panoramaHaloBatch: StarInstanceBatch
  focusedSurface: Mesh
  focusedCorona: Mesh
  surfaceMaterial: ShaderMaterial
  coronaMaterial: ShaderMaterial
}
```

命中检测采用 §6 的纯屏幕空间算法，不创建 `pickProxy` Mesh。`StarVisualHandle` 只记录数据身份与批次索引；共享资源可以由 thin instances、SPS 或经性能验证的等价批量实现承载，不向上层暴露具体 Babylon 类型。

职责边界：

- `StarVisualDescriptor`：纯函数，将 `StarDatum` 转换为颜色、亮度、表面活动、日冕尺度、远景视觉半径和命中半径；可单元测试。
- `StarVisualFactory`：创建共享几何、材质实例和每颗恒星的表现节点；不处理 React 状态。
- `StarPresentationController`：根据相机投影尺寸与主状态计算 LOD、透明度、hover/focus 强调；每帧只更新必要 uniform/实例数据。
- `StarPicker`：在屏幕空间计算候选恒星，负责 hover 与点击；不以 Babylon 球体真实投影轮廓作为唯一命中区域。
- `CameraFlightController`：拥有可取消的飞入/返回动画；不直接修改 React 业务状态。
- `BabylonRenderer`：编排上述单元，并继续通过 `onPick` 向 React 发送领域 `Star`。

`BabylonRenderer` 不继续膨胀为包含 shader、拾取算法和缓动细节的单文件实现。

为保证概念列表、键盘与指针走同一条路径，`MindverseRenderer` 新增：

```ts
focusStar(starKey: string): Star | null
```

`starKey` 必须使用既有 `starIdentity(star)`：现代数据返回 scope-aware `Star.id`，旧数据仅回退到概念文本 `Star.c`。Renderer 只在当前 `UniverseIndex` 中精确匹配；找不到、已销毁或当前位于答案地层时返回 `null` 且不改变相机或业务状态。成功时返回匹配的领域 `Star`，执行与指针选择完全相同的选中、飞入和 `onPick` 回调。React 概念列表必须先用 `starIdentity` 调用此命令，不再只更新本地 `star` 状态。

## 4. 数据到恒星外观

恒星的外观只表达已有数据中的规模、活跃度和关系强度，不把文章主题推断为物理属性。

- `star.color` / `kelvin`：决定星核基础色温；显示映射必须限制在可见色域，避免高温星全部烧成纯白。
- `bodyR`：决定近景物理半径与表面细节尺度。
- `bright`：决定星核曝光、光晕尺度和 Bloom 输入，但使用对数/限幅映射，避免少数恒星淹没画面。
- `burst`：决定日冕扰动、脉冲与局部耀斑频率；Reduced Motion 下只保留静态强度差。
- `seed`：决定噪声相位、表面斑驳和日冕形状，保证跨会话稳定。
- `rot`：决定表面缓慢自转；不改变恒星空间位置。
- 当前 OAuth 关系和现有模式过滤继续由既有领域逻辑控制，不在 shader 中重新解释。

同一输入、算法版本与画质档下，恒星外观必须确定性一致。

## 5. 三级视觉 LOD

### 5.1 LOD 0：宇宙全景

目标是“可读、可点、不过曝”。每颗恒星由面向相机的解析式光晕和高亮星核构成，投影后具有最小可读尺寸；不通过放大真实球体改变空间关系。

- 星核直径建议保持在 2–7 CSS px 的数据映射区间；高亮目标允许短时扩大到 9 px。
- 光晕为软边径向衰减，建议覆盖星核直径的 2.5–4 倍。
- 极少数高亮恒星允许轻微衍射芒；不得所有恒星同时出现十字闪光。
- Bloom 只承担溢光融合，恒星的基本可见性不能依赖 Bloom 是否开启。
- 相邻恒星过密时优先保持亮度层级，不通过显示更多轨道线增加辨识度。

### 5.2 LOD 1：接近恒星系

相机飞近后，星核 billboard 与球体表面交叉淡变，避免从平面光点突然跳成实体球。

- 开始显露球形边缘、明暗中心差和缓慢流动的表面纹理；
- 日冕成为第二层独立轮廓，活动强度由 `burst` 控制；
- 所属问题行星和轨道在飞入后半段渐显，不在点击瞬间硬切；
- 非所属恒星降低到约 12%–24% 的视觉强调，但不得完全消失。

### 5.3 LOD 2：恒星近景

目标恒星使用程序化 shader 表现等离子体表面：多尺度旋流噪声、亮暗胞状结构、边缘增辉和少量局部耀斑。它不是写实天体模拟，但需要呈现“正在活动的恒星”而非贴图球。

- 表面运动缓慢、连续，不能产生全屏频闪；
- 星核、表面和日冕的亮度分别限幅，保证色彩与纹理仍可辨认；
- 低画质减少噪声 octave、球体分段和日冕层数，而不是退回纯黑或纯色球；
- Reduced Motion 冻结或显著减慢噪声相位与脉冲，但保留完整静态外观。

## 6. 拾取与悬停

采用与旧版一致的屏幕空间语义拾取，而不是只依赖 Babylon `scene.pick` 的真实小球碰撞。

1. 将当前可见恒星中心投影到 CSS 像素坐标；
2. 排除相机背面、视锥外、当前模式不可见和答案地层中的恒星；
3. 按光标到投影中心的距离筛选；
4. 命中半径取视觉半径的映射值，并限幅到桌面 10–28 CSS px；触控使用 22–36 CSS px；
5. 多目标重叠时先选屏幕距离最近者，距离相同时选择相机深度更近者，再以稳定 star ID 决胜；
6. 在 `STAR_FOCUS` 中，已显示的问题行星优先于恒星；答案标本继续使用地层专用拾取。

拖动与点击必须解耦：指针累计移动超过 6 CSS px 后视为旋转，不触发点击。Pointer cancel、lost capture 和多指缩放不得留下 hover/pressed 状态。

悬停反馈包含：pointer 光标、光晕强度提升和 120–180 ms 的轻微星核放大。按下态只做短暂压缩/亮度收束，不改变相机，松开且仍命中同一恒星后才开始飞入。

## 7. 镜头飞入与返回

`CameraFlightController` 保存动画开始姿态、目标姿态、开始时间与当前 token。新飞行、用户主动拖拽、重置视图或进入问题行星会取消旧 token，迟到帧不得覆盖新状态。

- 飞入时长：普通模式约 900–1300 ms，随距离限幅；Reduced Motion 为单帧状态切换或不超过 120 ms 的淡变。
- 插值：相机 target 使用平滑曲线接近恒星位置；radius 使用对数空间插值，避免远距离后半段突然加速。
- 飞入过程中保留用户看到的方位，抵达后 ArcRotate 主动控制继续可用。
- 抵达阈值由恒星 `bodyR` 和恒星系可见距离共同计算，不写死为单一半径。
- 点击当前已聚焦恒星不重复启动动画。
- 点击空白：在恒星系状态返回全景；在行星状态先退出行星，再次点击空白才返回全景。
- 向外滚轮超过状态阈值时同样执行“行星 → 恒星系 → 全景”的逐级退出。

相机飞入开始时即可调用 `onPick(star)` 打开恒星信息面板；3D 行星与轨道按动画进度展开。若动画被用户主动旋转打断，恒星仍保持选中，控制权立即交给用户。

## 8. 轨道、行星与光照衔接

- 全景只显示宏观星群轨道，问题轨道和问题行星保持隐藏；
- 恒星飞入后半段只展开当前恒星的问题轨道和行星；
- 行星拾取优先级高于恒星，轨道线永不参与拾取；
- 选择行星后，目标恒星继续显示，但降低日冕动画对比，避免抢夺行星视觉焦点；
- 恒星可作为问题行星的视觉光源方向，但不得为每颗恒星创建昂贵的全场景动态阴影光；
- 进入答案地层时，恒星、光晕、命中代理、行星和轨道作为宇宙根节点整体停用。

## 9. 性能与资源约束

- 远景恒星使用 thin instances、SPS 或等价的批量方案，禁止为数百颗恒星创建数百个独立材质和后处理管线；
- 星核与光晕优先复用共享几何和 shader，通过实例属性传递颜色、强度、seed 与状态；
- 只有聚焦恒星启用高细分近景球与完整表面 shader；最多保留一个活动 LOD 2；
- 屏幕空间 picker 不创建代理 mesh，也不向颜色、深度或 Bloom pass 增加对象；
- 切换聚焦对象时复用近景资源，不反复编译 shader；
- `destroy()` 必须释放 observer、pointer listener、shader、实例 buffer 和相机动画；不得增加 WebGL context 数量。

性能基线固定为 Chromium、1440×900 CSS 视口、DPR 1、中等画质、版本化 500 恒星合成 fixture：预热 3 秒后采样 10 秒，普通全景的 p95 帧耗时不高于 20 ms；低画质 p95 不高于 33.3 ms。CI 只把相对既有基线恶化超过 20% 作为硬回归门槛，绝对帧率在记录型号的参考开发机上验收，避免不同硬件之间直接比较。测试 fixture 数量较少时，仍须运行这套密集星场性能 smoke test。

## 10. 错误与降级

- 高级恒星 shader 编译失败：降级为共享的解析式星核与光晕，不降级为空白或纯黑球；
- Bloom 不可用：星核和光晕自身仍提供完整轮廓；
- GPU/画质不足：减少表面噪声和日冕层，不减少可点击性；
- 相机动画异常：取消当前 token，稳定落在最近的合法主状态并报告 render error；
- WebGL context lost：沿用现有可读降级界面与重建流程；
- 数据值非法：描述符纯函数进行有限值检查与限幅，以稳定默认外观替代 NaN/不可见对象。

## 11. 无障碍与输入一致性

- 现有概念列表继续作为星图的语义等价入口，键盘选择必须以 `starIdentity(star)` 调用 §3 定义的同一 `focusStar(starKey)` 命令和镜头过渡；命令失败时列表保持原状态并呈现既有可恢复错误反馈；
- Canvas 上的 Esc 按状态逐级返回；恒星键盘选择继续由现有语义概念列表承担，不另造一套不可见的 Canvas 键盘候选状态；
- 不能只依赖颜色表达 hover 或 focus：同时使用尺寸、光晕轮廓和信息面板标题；
- Reduced Motion 不改变状态顺序和可操作功能；
- 触控命中半径独立扩大，单指旋转、双指缩放和轻触选择互不误触。

## 12. 验收标准

### 12.1 视觉验收

- 全景截图中能明确辨识不同亮度、色温和光晕尺度的恒星，不再呈现为同质点阵；
- 关闭 Bloom 后，恒星仍然可见并具有软边光晕；
- 飞入过程没有 billboard/球体跳变、全屏曝光闪烁或问题轨道瞬时爆开；
- 近景能看到连续活动的程序化表面和日冕，低画质也不是光秃纯色球；
- 行星聚焦时恒星仍作为空间参照存在，答案地层中宇宙层完全退出。

### 12.2 交互验收

- 在恒星可见光晕内点击能够稳定命中，不要求点中 1–2 px 星核；
- 移动不足 6 px 为点击，超过阈值为旋转；拖动结束不误触飞入；
- 悬停、按下、飞入、抵达和返回均有可见反馈；
- 重叠恒星选择结果确定且跨运行一致；
- 行星优先于恒星，空白点击和滚轮按层级正确退出；
- 用户在飞入途中主动旋转时立即获得控制权，不发生相机争抢。

### 12.3 自动化验收

- 描述符纯函数覆盖颜色、亮度、burst、非法值和稳定 seed；
- picker 覆盖最小/最大命中半径、重叠决胜、视锥排除、行星优先和拖动阈值；
- 相机控制器覆盖完成、取消、Reduced Motion、重复聚焦和逐级返回；
- 表现控制器覆盖 PANORAMA、STAR_APPROACH、STAR_FOCUS、PLANET_FOCUS 与 STRATA 的可见性/LOD；
- Babylon E2E 使用真实用户坐标点击光晕边缘，证明命中后出现恒星面板、镜头连续移动、问题轨道渐显；
- E2E 验证 hover 光标、拖动不误触、空白点击返回、Reduced Motion 和 context lost；
- 生产 build、lint、单元测试、Babylon E2E 与 `npm audit` 全部通过；
- 渲染基线至少覆盖全景、接近中点、恒星近景和行星聚焦四张图，并设置防止退回点阵/纯黑画面的像素与投影尺寸阈值。

## 13. 实施顺序边界

实现计划应按可独立验证的纵向顺序拆分：

1. 描述符与屏幕空间 picker；
2. 远景星核/光晕与 hover/pressed；
3. 可取消镜头飞行与逐级退出；
4. 问题行星/轨道的渐进展开；
5. 近景程序化表面与日冕；
6. 画质降级、无障碍、密集星场性能和渲染回归。

每一步先建立失败测试，再实现最小闭环；不得把“能显示”“能点击”和“能飞入”拆成长期不一致的用户可见状态。
