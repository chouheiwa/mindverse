# Babylon 写实行星渲染设计

日期：2026-09-04  
状态：待产品方复核

## 1. 目标

将当前问题行星从“带随机色块的发光球”升级为具有可信体积、地貌、昼夜面和大气层的写实天体，同时保留知见宇宙的数据语义：行星仍代表真实知乎问题，视觉差异必须能由答案证据、时间跨度、收藏/创作关系以及恒星辐照解释。

目标观感偏《星际穿越》的克制写实，而非霓虹赛博或纯装饰性科幻。用户在恒星系中应先看见可辨认的天体；聚焦后应看见山脉、盆地、撞击坑、冰层或熔岩等表面结构；继续进入时，星球画面自然让位于答案地层。

## 2. 当前问题

现有行星使用 IcoSphere 和自定义 ShaderMaterial，但渲染存在四个结构性问题：

1. `hash31(floor(...))` 产生离散随机单元，不形成连续地质结构。
2. 顶点位移后继续使用原始球面法线，地形没有获得对应明暗变化。
3. 固定光照方向与恒星位置无关，无法形成可信昼夜面。
4. 新鲜度、收藏和选中态直接叠加发光颜色，容易与 Bloom 一起洗白材质。

因此，本轮不以“增加更多贴图或辉光”为主，而是重建地貌、法线、光照和大气之间的职责边界。

## 3. 设计原则

### 3.1 数据决定地质，不替用户编造结论

- 恒星辐照与轨道距离决定热状态：熔岩、荒漠、岩石、冻原、冰封连续混合。
- 答案数量决定天体尺寸、地貌细节密度和小型撞击坑密度，不决定观点价值。
- 答案时间跨度决定断层与侵蚀尺度。
- 内容新鲜度决定大气可见度，不代表内容质量。
- 用户创作关系只表现为局部内热或夜侧微光；收藏关系只表现为克制的测绘标记。
- 数据不足时使用中性岩石材质并降低地貌复杂度，不随机补齐含义。

`PlanetSurfaceDescriptor` 是数据层和渲染层之间唯一的共享契约，字段与范围固定如下：

| 字段 | 范围 | 来源与缺省行为 | 渲染含义 |
|---|---:|---|---|
| `seed` | `uint32` | `questionId + starId` 的稳定哈希 | 所有程序地貌的确定性输入 |
| `radius` | `0.55..1.0` | `log1p(answerCount) / log1p(30)`；非法或缺失计为 `0` | 相对天体半径 |
| `detailDensity` | `0..1` | 与归一化答案数量相同 | 高频 octave 权重和小坑密度 |
| `faultStrength` | `0..1` | `log1p(timeSpanDays) / log1p(3650)`；无时间跨度为 `0` | 山脉 mask、断层尺度和 domain warp 强度 |
| `atmosphere` | `0..1` | 已有 freshness 截断至 `0..1`；缺失为 `0` | 大气密度，不改变地表价值判断 |
| `createdGlow` | `0` 或 `1` | 当前用户是否创作；身份未知为 `0` | 局部 HDR 内热强度开关 |
| `collectedMarker` | `0` 或 `1` | 当前用户是否收藏；身份未知为 `0` | 非发光测绘标记开关 |
| `incident` | `>= 0` | `starEnergy / max(distance², epsilon)`；非法输入归零 | 热状态连续混合的输入 |
| `thermal` | 五项和为 `1` | 沿用 magma/desert/rock/tundra/ice 五中心插值；无有效辐照为 ice | 地表色、粗糙度、发光和冰盖基线 |
| `craterCount` | `5..48` | 由归一化答案数量取整 | 生成预算；不是逐像素循环上限 |

本轮只扩展该契约，不改变已有答案数量、时间跨度、辐照、新鲜度和用户关系的业务定义。渲染模块不得直接读取原始知乎对象。
所有公式的输出必须显式截断到表中声明的范围，且不得把 `NaN`、`Infinity` 或负数传入 Shader。

### 3.2 各层只做一件事

- 地形层负责真实轮廓和大尺度高度。
- 材质层负责岩石、冰、沙和熔岩的颜色、粗糙度与局部发光。
- 光照层负责昼夜面、阴影、高光和边缘 Fresnel。
- 大气层负责薄雾、散射和黄昏边缘，不给地表统一描边。
- 后处理只压缩 HDR、抗锯齿和处理明确的高亮，不制造天体体积。

## 4. 总体架构

渲染采用“远景实例 + 恒星系行星 + 聚焦近景行星”三级 LOD，但共享同一个 `PlanetSurfaceDescriptor` 和确定性 seed。

### 4.1 远景

远景中的问题行星只保留稳定轮廓、热状态主色和受光方向，不计算高频地貌或大气积分。其职责是让用户识别恒星系层级和可点击目标。

### 4.2 恒星系视角

继续使用 IcoSphere，但以连续三维地形函数替换离散 hash。启用真实顶点位移、重建后的法线、恒星方向光和轻量大气壳。该层必须支持公转、主动旋转、拾取和渐显。

### 4.3 行星聚焦视角

选中行星后，不放大原有低精度轨道模型，而是将其视觉状态交接给一个独立的高细分聚焦模型。两者使用同一 seed 和 descriptor，因此地貌连续，但聚焦模型拥有更高网格密度、更完整材质与大气。离开焦点时反向交接，不创建第二份业务实体。

### 4.4 答案地层入口

进入答案地层时，相机靠近聚焦模型的选定落点。地表轮廓填满视口后，通过现有 `StrataTransition` 穿越表面；宇宙模型随后隐藏，答案地层成为唯一主场景。行星渲染本身不承载地层内容，避免“在宇宙上叠一层文字”。

## 5. 程序化地貌

### 5.1 基础高度

在归一化球面方向上采样连续 3D gradient/value noise，避免二维 UV 接缝。基础形态使用 4–6 octave fBm，低频控制大陆、盆地和缓坡，高频只提供近景细节。

### 5.2 地质组织

- 使用低频 domain warp 扭曲基础采样域，打破均匀噪声球。
- 使用独立 mountain mask，仅在部分区域叠加 ridged multifractal，形成连续山系。
- 使用 latitude、incident energy 和高度共同生成冰盖、沙漠或熔岩分布，避免整球单一颜色。
- 大型撞击坑由少量确定性 crater profile 生成，包含碗底、内壁和抬升环；小坑使用分桶后的局部程序单元补充。

同一个高度函数同时服务顶点位移、法线计算和材质分区，防止颜色地貌与几何地貌错位。

### 5.3 法线

第一版采用球面局部切向有限差分：在当前方向的 tangent/bitangent 两侧采样高度，构造位移后切线并叉乘得到法线。聚焦模型使用完整采样；恒星系模型可减少 octave。若性能不足，才在高细分模型上降级为 fragment derivatives。

## 6. 光照与材质

### 6.1 光源

每颗行星的主光方向由其世界坐标指向所属恒星坐标计算，不使用全局固定向量。地表基础光照使用 `max(dot(N, L), 0)` 形成清晰昼夜交界；非常窄的软化只处理抗锯齿，黄昏色交给大气层。

### 6.2 物理材质

材质采用简化 metallic-roughness/GGX：

- 岩石、沙地和冰均为非金属。
- 岩石粗糙度高，沙地更高且高光宽。
- 冰面粗糙度较低，掠射角高光更清楚。
- 熔岩的暗壳仍参与漫反射，裂隙通过 HDR emissive 发光。
- 夜侧保持低但非零的环境可读性，不用恒定灰色填平昼夜面。

材质参数在 linear space 中计算，由场景的 KHR PBR Neutral tone mapping 输出。开启 dithering 抑制暗部和大气色带。

### 6.3 Bloom 约束

提高 Bloom threshold，使普通日照地表不进入 Bloom。只有恒星、熔岩裂隙、创作内热和必要的观测反馈允许输出大于 1 的 HDR 颜色。Bloom 不得改变行星主体轮廓。

## 7. 大气层

恒星系与聚焦阶段使用独立、略大于地表的背面球壳。轻量 Shader 根据视线穿过球壳的路径长度、太阳方向、Rayleigh 主色和简化 Mie 前向散射计算亮度；夜侧受行星阴影抑制。大气厚度和密度由新鲜度映射，但设置上下限，避免满屏光环。

未来若实现从轨道连续下降至真实地表，可在单颗行星沉浸场景中接入 Babylon 官方 Atmosphere Addon 或 Bruneton 预计算 LUT。该讨论仅记录后续演进方向，不构成本轮需求。该能力不用于同屏多行星，避免为每个微缩天体维护场景级大气系统。

## 8. 组件边界

- `planetSurface.ts`：只将知乎证据转换为稳定、可解释的视觉 descriptor。
- `planetTerrain.ts`：提供确定性地形参数、LOD 预算和 crater 列表，不依赖 Babylon 场景。
- `planet.vertex.fx.ts`：计算球面位移和位移后法线输入。
- `planet.fragment.fx.ts`：计算地表分区、GGX 光照、夜侧和语义覆盖层。
- `planetAtmosphere.*.fx.ts`：只处理大气透射与散射。
- `PlanetVisual`：拥有轨道模型、聚焦模型、大气壳和材质生命周期。
- `PlanetFocusController`：负责两级模型交接、主动旋转、相机限制和返回路径。

业务数据、视觉参数和 Babylon 资源生命周期保持分离。Shader 编译失败时仅替换对应视觉层，不使整个宇宙退出。

## 9. 性能与降级

画质按行星投影直径占画布短边的比例选择，并使用固定滞回区间：

- 低：覆盖率低于 `0.035`；IcoSphere subdivision 3、3 octave 地貌、解析大气边缘、无小型 crater。
- 中：覆盖率进入 `0.045` 以上；IcoSphere subdivision 4、5 octave 地貌、有限差分法线、轻量大气壳；回落至 `0.030` 以下才返回低档。
- 高：仅当前聚焦行星可用，且覆盖率进入 `0.22` 以上；IcoSphere subdivision 6、6 octave 地貌、完整大型 crater 与局部小坑；回落至 `0.16` 以下返回中档。

首次创建时，覆盖率低于 `0.045` 选择低档，非聚焦行星达到 `0.045` 选择中档；聚焦行星低于 `0.22` 选择中档、达到 `0.22` 选择高档。后续切换才使用上述滞回阈值。

画布设备像素比上限为桌面 `2`、移动设备 `1.5`；不可见行星停止材质时间更新；大气只在球壳覆盖像素内计算。设备能力不足或 Shader 编译失败时按“高 → 中 → 低 → 简化 Lambert”顺序静态降级。本轮不引入 GPU timer、动态分辨率控制器或基于帧时间的自动升降档系统。

## 10. 交互

- 恒星系中点击行星触发镜头接近和模型交接。
- 聚焦后拖动旋转行星，滚轮或双指控制受限缩放。
- 旋转以惯性减速结束，不使用弹跳。
- 选中扫描线仅在交互瞬间出现并快速淡出，不长期污染材质。
- reduced motion 下取消惯性和长距离飞行动画，但保留状态交接与键盘操作。

## 11. 错误处理

- 高级地表 Shader 编译失败：切换至简化 Lambert 地表，保留点击和数据语义。
- 大气 Shader 失败或设备不支持：隐藏大气壳，不影响地表。
- 高质量模型创建失败：继续显示轨道模型并限制最大缩放。
- descriptor 出现非法值：使用中性岩石默认值，并记录诊断信息。
- WebGL context 丢失：沿用现有运行时恢复流程，重新从 descriptor 创建 GPU 资源。

## 12. 测试与验收

### 12.1 单元测试

- 同一 question/seed 始终得到同一地貌参数。
- 热状态、答案密度、时间跨度映射连续且有界。
- 光方向随恒星和行星位置变化。
- LOD 选择具有滞回且只有聚焦行星进入高档。
- Shader 契约包含位移法线、视线方向、粗糙度、发光和大气参数。

### 12.2 浏览器测试

- 点击行星仍能进入聚焦和答案地层。
- 拖动、缩放、返回、键盘和 reduced motion 正常。
- Shader 降级不会导致全屏黑色或文本 fallback。
- 场景切换后 RAF、监听器、材质和 mesh 数量不持续增长。

### 12.3 视觉验收

至少固定五个代表性 seed：熔岩、荒漠、岩石、冻原和冰封。基线截图必须满足：

1. 一眼可辨球体、受光面、夜侧和昼夜交界。
2. 山系连续，不呈现均匀颗粒或方格噪点。
3. 撞击坑具备坑底、内壁和抬升环，而非黑色圆斑。
4. 大气只在边缘与黄昏区域可见，不形成统一描边。
5. 普通地表不触发明显 Bloom，熔岩等发光区域仍保留细节。
6. 五种热状态不仅颜色不同，粗糙度、地貌组织和大气表现也不同。

## 13. 实施边界

本轮包含恒星系行星和聚焦行星的写实升级，以及进入答案地层前的视觉交接。不包含任何云层渲染，也不包含真正可行走的球面地表、全球 quadtree、天气模拟或流体海洋。Babylon Atmosphere Addon、Bruneton LUT、云层与这些地表级能力均为非规范性的未来方向，只有在后续需要从太空连续下降到地面时再进入独立设计周期。

## 14. 推荐实施顺序

1. 替换连续地貌函数并重建法线。
2. 接入恒星方向光和简化 GGX 材质。
3. 收紧 HDR、Bloom、tone mapping 与 dithering。
4. 增加轻量大气壳。
5. 增加聚焦专用高细分模型和交接。
6. 补齐主动旋转、性能分级和视觉基线。

这个顺序确保每一步都能单独观察收益，并且不会再次用后处理掩盖地表问题。
